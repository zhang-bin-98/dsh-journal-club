## 1. 技术选型

### 1.1 依赖全景（全部现成能力，零自研引擎）

| 能力 | 方案 | 说明 |
|---|---|---|
| PDF 解析（文本/阅读顺序/表格/图注/整图 bbox/LaTeX） | **官方 `mineru-open-api` CLI**（`npm i -g mineru-open-api`，OpenDataLab 官方维护） | **两档模式**：高精度 `extract -f md,json -o parse/`（需注册 mineru.net + 控制台 API Key，`auth` 命令或 `MINERU_TOKEN` 一次性配置——完整流程的默认与推荐档）；免费 `flash-extract`（免 token，≤10MB/20 页，**仅 Markdown 无结构化输出**——整图定位退化为 agent 视觉，skill 引导时明示差异，定位为试用）。长文用 dsh bash `run_in_background`；**缓存按 `parse/manifest.json` 精确命中**（见 4.2，防不完整/过期/换模式误复用）。自建端点不支持——README 将 dsh-pdf-mineru 列为隐私敏感备选 |
| 整页渲染 PNG、按 bbox 裁切 | **pdfjs-dist + @napi-rs/canvas**（Node，预编译零系统依赖） | 裁切用裁剪 viewport 从 PDF 重渲染（无损，不用压缩预览图） |
| 拼图组合 | **sharp**（libvips 预编译） | 布局计算纯 TS，贴图 sharp composite；产物登记 groups.json（见 4.2） |
| Panel 切分、标签识别、切分核对 | **agent 多模态视觉**（harness 托管） | 见 1.2；本地零 OCR、零 OpenCV |
| figures.json 写入通道 | **`update_figures` 工具**（本插件第 5 个原子工具） | json-patch + base-rev 乐观锁 + 原子替换 + 写前滚动快照；工作台（经 host RPC）与 agent 共用，防双写者覆盖（见 §3/§5） |
| LLM / 会话 / 文件 / 权限 / 预览 | dsh harness | 产品设计已定 |

运行环境：Node ≥ 22（与 dsh 一致）+ 全局 `mineru-open-api` + MinerU token。skill 内嵌 CLI 用法（含 flash/extract 模式选择、输出约定、后台跑法），用户无需安装任何其他 skill 或插件。

### 1.2 切分分工：agent 视觉为主力，crop 是反馈闭环

1. `mineru-open-api extract -f md,json` → `parse/` 落盘并登记 manifest；json（content-list）的 figure 块给出**整图 bbox**（agent 不用自己找整图）。
2. agent 看 `render_pages` 高清页图 + 整图 bbox → **视觉切分 panel**：经 `update_figures` 写入 figures.json（regions + panels 粗框 + 标签）。
3. `crop` 裁出 Panel PNG → agent（和用户）看裁切结果验证；不准则改 bbox 重裁——**迭代闭环**替代本地几何算法。
4. 图源核对工作台手调是最终兜底。

不做本地 OCR / 连通域几何：位图标签、无文本层 PDF 一律 agent 视觉处理；确不可判定的标疑点（产品规则不变）。

## 3. 工具契约（5 个原子工具）

所有工具：相对路径基于会话工作目录；返回 `ToolResult`（文本摘要 + 结构化落盘）；支持 `run_in_background` 与 `AbortSignal`。

| 工具 | 输入（zod） | 输出/副作用 |
|---|---|---|
| render_pages | `{ path, pages: number[], dpi?: 150\|300 }` | 写 `pages/<doc>-<NNN>.png`；返回路径列表 |
| crop | `{ figures_json, ids?: string[]（默认全部已采纳）, dpi?: 300 }` | 按 bbox 裁剪 viewport 渲染 → `figures/<panel_id>.png`，回写 asset 路径；返回清单与异常（越界/空框） |
| compose_panels | `{ assets: string[], layout_hint?: "grid"\|"rows"\|"1+2"…, output }` | 有限矩形分区布局（候选+评分，缩自 SmartJC 图组算法）→ `groups/<name>.png` + **登记/更新 groups.json 条目**（成员、输入指纹、布局几何）；返回预览路径与布局说明 |
| update_figures | `{ figures_json, patch: json-patch[], base_rev }` | **figures.json 唯一写入通道**：校验 base_rev（乐观锁，不匹配返回冲突与新 rev）→ 应用 patch → 原子替换写回 → 写前留滚动快照（`.history/`，保 N 份）。rev 单调递增，每次成功写 +1。agent 与工作台共用；用户手动编辑文件允许（下次写入遇 rev 冲突提示重载） |
| validate | `{ project_dir }` | 读 deck.md/outline.md/figures.json/groups.json → `{errors[], warnings[]}`；stdout 摘要 |

figures.json 的语义内容（切什么、怎么改）由 agent/用户决定——文件即真相 + agent 信任不变；`update_figures` 只是**写入通道与完整性保护**（防双写者 lost update、可回滚），不是审批流程。MinerU 编排同理：CLI 解析落盘 parse/，agent 读 content-list 经 update_figures 写整图 regions。

## 4. 数据契约

### 4.1 figures.json（核心，v1 schema）

```jsonc
{
  "version": 1,
  "status": "draft",            // draft | confirmed
  "revision": 3,                // 确认后每次结构变更 +1，下游失效判定用
  "documents": [
    { "id": "main", "path": "main.pdf", "role": "main", "pages": 38 },
    { "id": "supp", "path": "supplement.pdf", "role": "supplement", "pages": 24 }
  ],
  "figures": [{
    "id": "fig1",                       // 稳定 ID，文件名基础
    "label": "Figure 1",                // 原文图号；未标号可空
    "status": "pending",                // pending | viewed | adjusted | excluded
    "regions": [                        // 图块：单页 1 个 region（跨页多 region，v1 不拼接）
      { "document": "main", "page": 6, "bbox": [x0, y0, x1, y1] }   // pt，原页旋转后基准
    ],
    "caption": { "page": 6, "sentences": ["…", "…"] },
    "panels": [{
      "id": "fig1_A",                   // = asset 文件名主干（deck.md 引用锚点）
      "label": "A",
      "region_index": 0,
      "bbox": [x0, y0, x1, y1],
      "asset": "figures/fig1_A.png",    // crop 后回填；草稿期可空
      "caption_refs": [0, 3],           // caption.sentences 索引（多对多）
      "flags": [],                      // overlap | no-label | edge-cut | cross-page | missing-caption
      "origin": "auto"                  // auto（MinerU 整图）| manual（工作台）| agent（视觉切分）
    }]
  }]
}
```

规则：panel `id` 全局唯一且**永不复用**；`origin` 非 auto 的 panel 不被后续 agent 重切静默覆盖（skill 软约定 + 工作台不覆写标记）；确认后结构变更 `revision+1`，下游引用旧 revision 时 validate 给 warning。**whole-Panel 归一化**：无 Panel 的单图（整图直接采纳）表示为唯一一个 `label: null` 的 panel，bbox = region bbox——数据与裁切无特判，deck.md 引用方式与普通 panel 一致。写入一律经 `update_figures`（rev 乐观锁）。

### 4.2 其余契约文件

- `jc.md`：见 [对话入口](../product/对话入口.md) §5（frontmatter 含 **confirmations 段**——每个确认点记录内容摘要/revision 与时间；恢复时以 digest 比对判定确认是否仍有效）。
- `groups.json`：**图组清单（组合图的机器可读来源契约）**：

```jsonc
{
  "version": 1,
  "groups": [{
    "id": "fig4_AD",                       // = groups/<id>.png 文件名主干
    "asset": "groups/fig4_AD.png",
    "members": ["fig4_A", "fig4_B", "fig4_C", "fig4_D"],   // panel id 引用
    "inputs_digest": "sha256:…",           // 成员 panel 资产内容指纹（重裁后不匹配→提醒重建）
    "layout": { "kind": "grid", "geometry": "…" }          // 分区几何（重拼同布局可复用）
  }]
}
```

validate 将 deck.md 中的 group 引用**展开为成员 panel** 检查身份与存在性；inputs_digest 不匹配（成员被重裁）→ warning 提醒重建拼图；deck 确认记录包含 groups digest（拼图变更使确认点 3 失效）。

- `parse/`：MinerU 产物存档（markdown、content-list、images、layout），根部 `parse/manifest.json` 为**缓存清单**：

```jsonc
{
  "documents": [{
    "id": "main", "source_sha256": "…", "mode": "extract",   // extract | flash
    "cli_version": "x.y.z", "artifacts": ["md", "content-list", "images"],
    "status": "done"                                          // done | partial（中断/失败）
  }]
}
```

缓存命中条件：源摘要 + 模式 + status=done + 产物齐全四条全中——防止补入补充材料、解析中断残留、免费→高精度切换时误复用；partial 结果保留用于断点续传但不视为成功。analysis.md 生成的证据底料即此目录，agent 按需分页读取；**paper.json 不再是必需产物**（agent 直读 content-list；若 M3 发现上下文开销大，再补轻量聚合工具——待定项）。
- `analysis.md` / `outline.md` / `deck.md`：人读契约，格式见 [deck 格式](../product/deck格式.md) 与产品设计 4.6；validate 只解析 deck.md 固定标记（页头注释/来源行/讲稿块），**发现覆盖等语义检查归 agent**（skill 剧本：确认前对照 analysis.md 发现清单自查）。

### 4.3 项目文件夹布局（全量）

```text
<论文名>/
├── jc.md  main.pdf  supplement.pdf
- `parse/`                      # MinerU 产物存档 + manifest.json（缓存清单）
├── pages/                      # render_pages 页图底图

```

## 5. UI 结构要点

- **技术底座（零新增）**：React 由宿主提供（peer，client 插件渲染进宿主 React 树）；状态 = React hooks + 文件 watch 轻 store，不引状态库；样式 = CSS Modules + `--dsh-alias-*` 语义 token（明暗主题自动跟随）+ `ui-primitives` 共享控件；不引任何 CSS 框架。
- **JC tab**（`ctx.sidebarRightTabs.register`）：三态——空态（引导 + 轻发现 jc.md 项目）/ 状态卡（读 jc.md + 产物实况）/ 核对工作台（读 figures.json，fs watch 自动刷新，最近变更高亮）。
- **核对工作台**：Figure 列表（页图底图 + 框叠加，pt→px 按底图 DPI 换算）、四角手柄、裁切预览（从 pages 底图裁显示；正式资产仍由 crop 从 PDF 重裁）、图注高亮（caption_refs）、放大编辑（面板内 modal）。写路径：**UI 编辑 → host RPC 调 `update_figures`**（dsh `workspaceFiles` 为只读服务，client 不能直写；host 侧 service 是唯一落盘通道，与 agent 同一乐观锁协议——UI 与 agent 的并发修改互不覆盖，冲突时提示重载）。
- **聊天轻卡片**（ConversationNode）：图源卡（摘要 + 打开工作台 + 快捷确认）、outline/deck 确认卡；按钮经 `agent.followup()` 回流标准指令文本（`/jc confirm figures` 等——指令即文本，无隐藏协议）。

## 6. skill 剧本骨架（skills/journal-club/SKILL.md）

1. 触发与分流（完整流程 / 局部任务 / 恢复；边界判断：原创研究；检测 `mineru-open-api` 可用与 token，给安装/注册引导）
2. 步骤 1 论文分析：检查 token——未配置发注册引导（mineru.net 注册 → 控制台 API Key → `auth` 配置），拒绝注册时明示差异降级 flash-extract 试用 → bash `extract -f md,json -o parse/`（后台；**缓存按 parse/manifest.json 四条件命中，不完整/换模式/换文档不复用**）→ 读 content-list → 建 jc.md / figures.json（整图 regions + captions 归组，经 update_figures）→ `render_pages`（figure 页 + 疑点页）→ **agent 视觉切 panel**（经 update_figures 写粗框与标签）→ `crop` → agent 看裁切结果迭代粗框 → analysis.md 生成规则（发现覆盖、引用块+页码、疑点标记）
3. 确认点 1：引导右侧栏工作台；确认 = `/jc confirm figures` → crop 全量 + revision 定稿 + 写 jc.md confirmations（revision）
4. 步骤 2 outline.md：叙事策略（继承 SmartJC 五策略）、主线/补充、内嵌图引用规范
5. 确认点 2：`/jc confirm outline` → 写 jc.md confirmations（outline digest）
6. 步骤 3 deck.md：分页规则、compose_panels 编排（何时拼图、layout 提示、groups.json 登记）、validate 通过才算完成
7. 确认点 3：`/jc confirm deck` → 写 jc.md confirmations（deck digest + groups digest）→ PPTX 编排（dsh-ppt-maker 检测 → ppt_* 调用序列 → 讲者备注 → 质检导出；备选路径）
8. 行为约定：冲突先说明、大范围先讲计划、不跳确认渲染、requirements 优先、科学表达红线（不编造/不升级因果）；**figures.json 修改一律走 update_figures**（不用通用编辑器，防并发覆盖）；发现覆盖自查（outline/deck 确认前对照 analysis.md 发现清单，缺口写入回复）
9. 恢复语义：读 jc.md + 产物实况，按断点续跑；**确认有效性按 digest 比对**（confirmations 记录 vs 当前文件/图组内容），不一致或无记录时**停在该确认点等用户**，不自行推进

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| mineru-open-api CLI 输出契约（json 是否= content-list、images 是否随包、坐标基准） | M1 首项实测；不符则在 skill 层适配（CLI 输出→parse/ 规整脚本属工具层小函数，不引新依赖） |
| agent 视觉切分精度不足 | crop 反馈迭代闭环（裁→看→改→重裁）；核对工作台手调兜底；M2 是卡点，不达标再加轻量几何辅助工具（候选，不预建） |
| MinerU bbox 与 pdfjs 坐标不一致（旋转/裁剪页） | M1 验收项；skill 与 figures.json 写入时规整；异常页人工框 |
| mineru-open-api / dsh-ppt-maker 为外部依赖（API 变动、服务可用性） | 前者为官方维护 CLI（风险最低）；均为编排层依赖（我们的 5 工具不依赖它们）；skill 检测 + 明确引导 + 失败如实报错；README 注明版本 |
| MinerU 云端隐私（论文上传） | README/设置明示；自建 v2 端点是官方支持的替代 |
| @napi-rs/canvas / pdfjs Node 渲染成熟度 | M1 卡点验证（fixture 固定回归）；备选 pdf-to-img 封装包 |
| 长会话上下文膨胀（论文长、content-list 大） | content-list 分页按需读取；analysis 生成走分页批次；必要时 M3 补聚合工具（4.2 待定项）；harness 压缩兜底 |
| ~~dsh client 写文件接缝不确定~~（已解决：workspaceFiles 只读，host RPC + update_figures 唯一通道） | M4 首项以 host RPC 跑通核对工作台写路径；乐观锁冲突用例入 M2 验收 |
