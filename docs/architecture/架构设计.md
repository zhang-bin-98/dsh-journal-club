# 架构设计

本文维护技术结构、文件契约、开发发布与验证边界。产品行为见 [产品设计](../product/产品设计.md)；安装入口见 [README](../../README.md)。运行时流程由随包 `journal-club` skill 执行，不依赖用户访问本仓库文档。

## 1. 分层与依赖

单 npm 包 `dsh-journal-club`，包含 Cordis host 插件、client 工作台、五个原子工具和 skill。各阶段以文件解耦，工具不感知完整流程；UI 写入复用工具核心，展示与刷新以文件为准。

| 层 | 职责与实现 |
|---|---|
| 宿主 | DSH 提供模型、会话、权限、文件读取/监听、Markdown 与图片预览 |
| skill | 分流、解析编排、视觉切分、学术叙事、三个确认点、恢复及 PPTX 编排 |
| host / service | 会话路径解析、Remote 桥接、文件边界与确定性读写；不复制流程状态机 |
| client | React 工作台和聊天卡片；文件 watch + 轻量 hooks/store，不引入状态库 |
| PDF | `pdfjs-dist` + `@napi-rs/canvas`，页图及裁剪 viewport 从 PDF 重渲染；首页身份由 agent 读图识别，页数取工具返回值，无需 Python PDF 引擎 |
| 拼图 | 纯 TS 几何与布局评分，`sharp` 合成；UI 和导出共用等比适配与像素取整 |
| 外部编排 | 随包 Node runner 调用官方 MinerU API 解析全文，dsh-ppt-maker 创建/检查/导出 PPTX；五个本地工具不依赖二者运行 |

Node 最低版本为 22.13，开发与 CI 使用 Node 24。宿主 API 仍为预发布接口，声明的 DSH `>=0.2.0-0` 不代表所有版本均已验证。工具参数使用 DSH DSL 与 canonical output；Zod 用于内部数据契约，不作为宿主工具注册 schema。

### SmartJC 复用

SmartJC 源码位于 `E:\project\SmartJC`，只读参考，不修改或引入其仓库运行时依赖。先复用再新增实现，适配时保留算法与科学规则语义。

| 级别 | 复用内容 | 适配边界 |
|---|---|---|
| A：纯函数与内容资产 | `computeLayout.ts`、`figureGeometry.ts`、图注/证据规则、分页逻辑与五类研究策略 | 浏览器外壳改为 Node/文件接口；原私有 Claim/Source/页面 JSON 改为 Markdown、页码和 Panel ID |
| B：规则移植 | 图文引用、讲稿校验、叙事覆盖、图源变更影响、分析/大纲/分页工作流与识图步骤 | 确定性规则进工具，领域流程进 skill；不搬候选审批契约 |
| C：参考适配 | PDF 渲染与裁切数学、框选与手柄、图注高亮、分批分析保存 | 使用宿主 React、主题和 Node PDF 环境，不照搬整体 UI |
| D：不复用 | IndexedDB、pi-agent-core、PWA、PptxGenJS、原三栏工作台 | 分别由普通文件、宿主能力和生态 PPT 插件承担 |

## 2. 代码结构与宿主接口

| 位置 | 职责 |
|---|---|
| `src/index.ts`、`src/host.ts` | 注册工具/skill/JournalClubService；Typert Remote 按 session 解析 cwd，委托共享服务 |
| `src/tools/` | `renderPages`、`crop`、`composePanels`、`updateFigures`、`validate` 工具入口 |
| `src/figures/`、`src/groups.ts` | 图源 schema/写入核心；图组清单、内容摘要与成员指纹 |
| `src/compositionService.ts`、`src/layout/` | 拼图载入/保存、文稿顺序、图源过期判定与共享几何 |
| `src/project/`、`src/project.ts` | jc.md 状态、摘要与确认 helper；经包子路径 `dsh-journal-club/project` 导出 |
| `src/paths.ts`、`src/files.ts`、`src/fileLock.ts` | 路径边界、原子写、SHA-256、取消检查与文件锁 |
| `src/pdf/`、`src/validate/` | PDF 缓存/坐标/MinerU 换算；文稿解析及一致性规则 |
| `src/mineru/` | 官方 API 提交/上传/轮询/流式下载、ZIP 校验、任务恢复与缓存；构建为 `lib/mineru.js` |
| `src/client/` | 页签、卡片、文件 store、图源核对、拼图和主题样式 |
| `src/skills/journal-club/` | `SKILL.md`、formats/narrative 与 research 参考；随包运行资产 |
| `scripts/`、`tests/` | 构建/Remote 生成/打包与发布校验；固定 fixture 回归 |

host 与 client 分别构建。React/React DOM 由宿主提供，不打包第二份；client 使用 `window.__ModuleLoader__.load({id, factory})` 工厂契约，模块级导出 `inject`，由 loader 等待服务后调用 `apply`。工厂内不能有 CSS import，样式以 `jc-` 前缀字符串注入并更新同一 style 节点，消费实测 `--dsw-alias-*` / `--dsw-font-family` token。交互蓝和冷灰编辑底色单独定义，控件与 dialog 使用原生元素；不引组件库或 CSS 框架。

`JournalClubService` 继承官方 `TypertRemoteService`，方法声明 sessionId 资源访问。构建脚本为官方生成器准备临时 workspace，生成 `./typert` 和 `./remote`，不手写 wire descriptors，不依赖宿主源码仓库。新增 Remote 或更新安装后完整重启宿主，避免 client 已更新而 host 仍保留旧接口；404/读取失败显示不可用，不能当作文件不存在。

client 的 `workspaceFiles` 负责分页读取和监听，写入通过 host RPC。Remote 文件访问限定当前 session cwd，检查词法范围及 realpath，阻止符号链接越界；原子工具相对路径基于会话 cwd，也接受显式绝对路径，不能把 Remote 范围检查描述成所有工具的全局沙箱。Panel ID 拒绝路径穿越和 Windows 保留名。预览经宿主 `sidebarRight.openResource()` 打开。

聊天卡片标记为 `<!-- jc-card {"project":"论文目录","stage":"figures"} -->`，stage 可为 figures/outline/slides；卡片不是状态或确认记录。确认按钮通过 `sessions.scope(sessionId).get('conversation').send(text)` 发送带项目路径的标准指令，不回退到其他会话。拼图「加入对话」使用 Session 提供的 `inputActions.captureInsertion/insertText` 插入原生文件引用，不发送消息。

## 3. 五个工具与写入完整性

路径相对会话工作目录，工具返回摘要与实际文件路径，支持后台运行与取消；完整 schema 以 `src/tools/` 为准。

| 工具 | 主要参数 | 产物与约束 |
|---|---|---|
| `render_pages` | `path, pages, dpi?` | 写 `pages/<doc>-<NNN>.png`；返回总页数及 PNG 尺寸，常用 150 DPI 预览、300 DPI 识别，文件名碰撞加稳定标识 |
| `update_figures` | `figures_json, patch, base_rev` | 唯一图源写入核心；JSON Patch、版本比较、完整性校验、快照和原子替换 |
| `crop` | `figures_json, ids?, dpi?` | 默认裁切未排除 Panel，输出 `figures/<panel_id>.png`，经同一写入核心登记 asset；局部坏项列 anomalies，不冒报成功 |
| `compose_panels` | `assets, layout_hint?, geometry?, scale?, output, create?` | PNG + groups.json；默认更新已登记 output 并保留 ID，未登记路径报错；显式 `create:true` 才新建且不得覆盖 |
| `validate` | `project_dir` | 检查 figures/groups/outline/slides，返回分开的 errors/warnings，不替代语义评审 |

agent 视觉判断 Panel 边界，正式框写入和图像执行复用上述工具；不自建空白带/阈值/轮廓分割，不以 Python/Pillow/NumPy 脚本替代裁切、拼图或直接覆盖资产。工作台的 `pageInfo`、`updateFigures`、`cropPanels`、`compositionState`、`saveComposition` 是复用同一核心的会话作用域 UI 接口，不新增模型工具。当前 agent 没有标尺/批量核对图接口，普通核对直接读实际图像；临时联系图不登记为汇报图组。这一范围不限制 PPT/PPTX 构建与排错脚本。

### 图源写入

- 支持 RFC 6902 风格的 add/remove/replace/move/copy/test 与 JSON Pointer；拒绝危险对象键、非法数组索引和未知操作。revision 由服务维护，除 test 外不能直接 patch。
- 同路径进程内队列与独占 `.lock` 文件串行写入；锁内重读并比较 `base_rev`，匹配后应用 patch 和跨字段校验，成功 revision +1。冲突不改主文件或生成快照。
- 缺文件且 `base_rev=0` 时从空 documents/figures 初始化，patch 必须补齐至少一个 document；首次成功 revision=1，不生成虚构快照。已有文件写前在 `.history/` 保留最近 10 份旧版，临时文件完整写入后 rename。
- crop 可在锁外渲染暂存图，但必须在 figures 锁内确认 revision 未变，再替换 PNG 和一次登记新 asset；单次裁切至多推进一次 revision，已登记 asset 仅换像素不增版本。像素先落盘，避免登记悬空引用；失败如实报告，不宣称跨文件事务。
- 锁记录 pid，已退出进程的锁可回收；空或损坏锁超过 5 秒后尽力回收，删除前复读。跨进程极端竞态与网络文件系统行为不视为已验证。

### 拼图写入

`groups.ts` 是清单解析与成员指纹的唯一实现。载入同时返回清单内容和摘要；保存于 groups 锁内检查载入时的 `base_digest` 与输入图片摘要，渲染后再次检查输入，过期即报冲突。组合 PNG 原子替换，清单写失败尝试恢复原 PNG；不宣称多文件事务。修改既有条目保留 ID/asset 及原位置，只有新建追加；不建别名表或按成员自动合并。

UI 保存与 agent 调用共用 `composePanels`。刷新图源不推进布局并发版本，读取成功后复用保存函数重建当前图，普通刷新不能绕过外部布局冲突。编辑过程不逐帧写盘。

## 4. 文件契约

```text
<论文目录>/
├── jc.md                    # 要求、流程提示与确认记录
├── main.pdf / supplement.pdf
├── parse/                   # 解析产物及 manifest.json
├── pages/                   # PDF 页图
├── figures.json / figures/  # 图源元数据与 Panel PNG
├── .history/                # 图源滚动快照
├── groups.json / groups/    # 拼图布局与组合 PNG
├── analysis.md / outline.md / slides.md
└── render/                  # 派生 PPTD/PPTX 等，可重建
```

图源、拼图、内容和确认记录各自独立。`jc.md` 不重复存图源或布局；PNG 不替代 JSON 中的身份与几何。文稿统一命名 `slides.md`，不提供旧文稿名别名或双读。

### 4.1 figures.json

基础 schema 与跨字段规则集中在 `src/figures/schema.ts`，写入与 validate 复用。

```json
{
  "version": 1,
  "status": "draft",
  "revision": 3,
  "documents": [{"id": "main", "path": "main.pdf", "role": "main", "pages": 12}],
  "figures": [{
    "id": "fig1", "label": "Figure 1", "status": "pending",
    "regions": [{"document": "main", "page": 3, "bbox": [40, 80, 550, 500]}],
    "caption": {"page": 3, "sentences": ["(A) Experimental design."]},
    "panels": [{
      "id": "fig1_A", "label": "A", "region_index": 0,
      "bbox": [40, 80, 550, 250], "asset": "figures/fig1_A.png",
      "caption_refs": [0], "flags": [], "origin": "agent"
    }]
  }]
}
```

- 根 status：draft/confirmed；Figure status：pending/viewed/adjusted/excluded；document role：main/supplement；Panel origin：auto/manual/agent。caption 和未裁切的 asset 可缺省，图号或 Panel 标签可为 null。
- document/Figure ID 各自唯一，Panel ID 全局唯一；稳定身份不得随改标签或重新裁切改变或复用。asset 必须为 `figures/<id>.png`，caption_refs 是句子索引，支持多对多；flags 为疑点字符串数组。
- bbox 为旋转后 PDF 页面上的 pt `[x0,y0,x1,y1]`，有限、非负、正面积；Panel 在关联 region 内，页码及文档引用有效。人工框超过初始 region 时同次 patch 外扩 region，不取消包含校验。
- MinerU bbox 两轴各自归一化为 0–1000，按 `pt = norm / 1000 × 旋转后对应页尺寸` 转换；使用 `src/pdf/mineru.ts` / project helper，不用渲染像素宽度猜坐标。正式裁切来自原 PDF，预览缩放与持久化坐标无关。
- 无子图的整图表示为一个 label=null 的 whole-Panel；必要时可在保留原字母 Panel 及疑点的同时增加整图兜底。跨页 region 可记录，当前不拼接多页图像。
- 图注 page 是起始物理页，核实的续文进入 sentences；完整范围写入分析底稿。非 auto 的人工/agent 框不得被重切静默覆盖，这是 skill 行为约定，不是 schema 审批门。

### 4.2 groups.json

```json
{
  "version": 1,
  "groups": [{
    "id": "fig1_AB", "asset": "groups/fig1_AB.png",
    "members": ["fig1_A", "fig1_B"],
    "inputs_digest": "sha256:…",
    "layout": {
      "kind": "manual",
      "geometry": {"width": 620, "height": 200, "cells": [
        {"member": "fig1_A", "x": 0, "y": 0, "width": 300, "height": 200},
        {"member": "fig1_B", "x": 320, "y": 0, "width": 300, "height": 200}
      ]}
    }
  }]
}
```

示例摘要为占位，实际由成员资产内容计算。cells 与 members 一一对应，无重复/遗漏，数值有限、尺寸为正；kind 支持 manual/grid/rows/1+2。已登记 ID 和 asset 是稳定引用，不能依据新成员推导新名字。

geometry 保存图片包围框；图像在框内等比 contain，每次按当前图片比例计算，不持久化可派生的 content。显式输入的画布宽高只是参考，不作裁切边界；先适配图片再取实际外缘、平移至原点，保留内部间隔和全部科研像素。图片按 cells 顺序绘制并登记成员，默认导出 2 倍像素，工具可指定 scale；这不增加原始细节。不限制比例或图数，旧 gap/content 字段读取忽略、保存移除。

成员图片重裁后 inputs_digest 不匹配，提示重建；图组清单变化会使 slides 的 groups_digest 确认失效。完整流程只在清单不存在时创建 `{"version":1,"groups":[]}`，无拼图也计算实际文件摘要。

### 4.3 jc.md 与解析缓存

`jc.md` 使用 frontmatter 保存 title、main_paper、可选 supplement、stage、requirements、confirmations、updated，正文为自由备注。stage 枚举 analysis/figure-review/outline/slides/render/done，**仅是流程提示缓存**，不能证明产物完整或确认有效。

| 确认记录 | 与当前文件的比较 |
|---|---|
| `confirmations.figures: {revision, at}` | figures.json revision |
| `confirmations.outline: {digest, at}` | outline.md 原始字节 SHA-256 |
| `confirmations.slides: {digest, groups_digest, at}` | slides.md 与 groups.json 原始字节 SHA-256 |

摘要格式为 `sha256:<64 位小写十六进制>`，不归一化 BOM、换行或空白。缺记录为 missing，不匹配为 stale；stage 或 figures.status 不能代替比较。jc.md 不再保存重复的 figures_revision，outline/slides frontmatter 的 figures_revision 则标明内容所依据的图源版本。读写与比较复用 `dsh-journal-club/project` helper。

`parse/manifest.json` 由 API runner 维护。documents 条目包括 id、source_sha256、mode（extract/flash）、provider=mineru-api、parser_version、options_digest、任务标识、上传状态、artifacts、artifact_sha256 和 status（done/partial）。高精度记录 batch_id，flash 记录 task_id；artifacts 是相对 parse 根目录的真实路径。源、模式、参数、provider/parser 版本均匹配，且 done 和所有资产摘要有效才命中缓存；缺失或篡改的结果从已保存任务恢复。partial 保留诊断/恢复信息，不冒充成功，不手工写 done。旧 CLI 记录可保留追溯，但不自动当作 API 缓存；补充 PDF 独立处理，agent 分页读取内容，不另建 paper.json 聚合真相。

### 4.4 文稿契约

analysis 记录原文证据和页码，outline 记录叙事计划。slides 由 YAML frontmatter、`---` 分页、页头注释、正文与可见讲稿构成；相对图片路径指向 figures/groups。下面是格式示例，不代表真实论文结论：

```markdown
---
title: 文献汇报
paper: main.pdf
figures_revision: 3
generated: 2026-11-01
---

<!-- page 1 · layout: figure-text -->

# 实验设计与主要观察

![Figure 1A](figures/fig1_A.png)
> 来源：Figure 1A · p.3

> 🗣 **讲稿**：先说明实验分组与对照，再介绍图中的观察。
> 讲述提示（不口播）：此处留出读图停顿。
```

页号从 1 连续并与分隔顺序一致。layout 是可省略的排版建议：title/text/figure-full/figure-text/two-figures/panel-grid；未知元数据不承载流程状态。页标题用 `#` 或 `##`，图片用标准 Markdown。补充图保留原 S 编号，如 `> 来源：Supplementary Figure S9 · p.27 · 补充材料`，不能为过校验改成主图。

每页必须有固定 `> 🗣 **讲稿**：` 标记及完整讲稿，续行沿用引用块。转 PPTX 时完整写入对应页 notes，仅去掉 Markdown 格式，逐页比对正文；备注数量齐全不等于全文正确。宿主可能显示页头注释原文，不因此另建渲染器。

### 4.5 校验边界

- **errors**：图源跨字段不合法、页头/页号/来源不合法、图片不存在或身份不明、图组成员无效、每页讲稿缺失等。图源校验同源，统一报告 FIGURES_INVALID。
- **warnings**：引用旧 figures revision、图组输入指纹不符、Panel 未引用、页内图与讲稿提及不对应。outline 只做存在/版本等确定性检查。
- **agent 与人工检查**：发现覆盖、正文主图的可读展示、科学因果边界、讲述节奏与实际 PPTX 视觉效果。程序不承诺理解这些语义，也不把提醒变成局部工具审批门。

## 5. UI 状态与同步

- 项目发现只扫描 cwd 和一级子目录；概览用现有确认摘要 helper 派生状态，不新增后端状态库。文件读取错误区别于不存在，临时失败重试一次，仍失败保留上次内容并提示；内容损坏或文件删除按真实状态处理。
- `browseLocation.ts` 用 `journal-club.browse.v1.<sessionId>` 本地键保存项目路径和 view/figure/panel/group；这是浏览偏好，不能保存确认、进度或草稿。存储不可用仍可工作，显式入口优先于记忆，后台文件更新不跳页。
- JC tab 使用 keepMounted，页面以 hidden 保留编辑器；复用宿主 registerCloseHandler 和项目切换检查保护未保存草稿。宿主卸载或退出仍可结束内存状态。
- 图源编辑在操作开始时捕获 revision，写入串行排队，仅跨过本端可安全识别、不改变既有 Panel 下标的版本推进；外部写入与删除继续报冲突。`cropPanels` 返回 base_revision 供识别。watch 不覆盖未提交标签，不因无关刷新清空页图。
- host 的 pageInfo 返回原 PDF 旋转后尺寸；client 按 pt 映射页图和框。改框经 updateFigures → cropPanels，两者复用工具核心，不能直接用只读 workspaceFiles 写文件。
- compositionState 读取清单、素材尺寸/摘要与文稿引用顺序；无 figures.json 时只按已登记 members 找规范 `figures/<id>.png`，缺图明确提示。parseSlides 派生顺序，不写额外排序文件。
- 拼图监听 groups.json、slides.md 与 groups 目录，外部变化更新无脏草稿图组及缩略图；脏草稿保留几何、撤销历史和 CAS base，显式重载才放弃。保存或手势中延后通知，刷新图源不擅自重排或解除冲突。
- 适应视图按图片外缘派生，手势中冻结、结束后取景；编辑区余量不写进布局。缩略图复用 PNG/文件缓存，接近可见时加载，不建缩略图服务。
- 加入对话前捕获输入版本，必要时复用保存逻辑后插入 ID/PNG/groups.json 引用，保留原输入及选中文字。输入变化或组件卸载时不补插过期引用。

## 6. 外部能力与降级

### MinerU API runner

完整流程默认高精度 extract，通过随包 Node runner 调用官方 MinerU API；解析算法仍由官方服务提供，论文会上传云端。本地五个工具不依赖认证。旧 CLI 0.5.9 的结果下载受独立 60 秒 HTTP 超时影响，提高其 extraction timeout 无法解决；本实现改为可恢复的薄 API 传输层，无需全局 CLI，不使用调试模式绕过。

- **入口与参数**：skill 注册时获得绝对 runner 路径，先查看 `node "<runner>" --help`。主文执行 `node "<runner>" main.pdf --output parse --id main`，补充材料使用 `supplement.pdf` 和 `--id supp`。支持 `--mode extract|flash`；extract 默认 vlm/ch、ocr=false、formula/table=true，可指定 model、pages、language 和 ocr/formula/table。
- **认证与降级**：高精度依次读取 `MINERU_TOKEN`、已有 `~/.mineru/config.yaml` 中的 token，不从参数接收或打印配置。flash 不读 token，仅在用户选择后使用，为 ≤10MB/20 页、仅 Markdown、无结构化定位的受限试用，限制以实际响应为准。不宣称当前 runner 支持本地/自建服务端点；数据边界见 [SECURITY](../../SECURITY.md)。
- **提交与恢复**：高精度通过 `/api/v4/file-urls/batch` 申请上传、PUT 原文件，再按 batch_id 查询 `/extract-results/batch/<id>`；flash 使用 `/api/v1/agent/parse/file` 与 `/parse/<task_id>`。先保存任务标识，再上传。下载失败重跑相同命令，复用任务查询和下载，不拆页重新提交。源或参数变化、显式 `--restart` 才新建任务；失败云端任务先调查。POST 提交不自动重试，响应丢失且未取得 ID 时无法保证去重。签名上传地址不落盘，上传中断且云端仍等文件时需显式 restart。
- **超时与重试**：请求 60 秒、上传/下载 600 秒、轮询 1800 秒；`--request-timeout`、`--download-timeout`、`--poll-timeout` 均为秒。查询/上传/下载遇网络失败、429、5xx 默认最多退避重试两次，其他 4xx 不重试。下载地址失效时重跑命令重新查询取得地址。取消信号传至请求、流及解包；当前不承诺 Range 字节断点续传。
- **产物与完整性**：一次高精度任务返回 Markdown、content-list 和图片，规范化为 `parse/main/main.md`、`main.json`、`images/`（补充材料对应 supp），保留其他官方资产。ZIP 流式临时落盘、yauzl 流式解包并验证大小/CRC，拒绝路径穿越、符号链接及重复文件；验证非空 Markdown、清单结构和图片引用后才发布输出并标 done。目录替换失败尝试恢复旧目录，不宣称跨文件事务。
- **状态与命令结果**：manifest 是持久任务和缓存事实，文档锁及短时 manifest 锁处理主/补并发；不另建状态库。token、签名 URL 和服务响应正文不进项目或日志，错误仅报告阶段与状态码。PowerShell 须立即保存 Node 退出码，并在读日志后传播；末尾读日志成功、后台 completed 标签或普通 stderr 不能证明解析成功。

宿主在 runner 启动前失败时走正常命令授权或重试；不改项目/父目录 ACL，不将下载错误判断为 PDF 损坏、认证失败或静默切换解析引擎。降级需说明实际能力限制并尊重用户选择。

**PPTX**：先调用已安装的 ppt-maker skill，再发现实际 ppt_* 工具并读 schema；初始列表无工具不代表未安装。已实测 dsh-ppt-maker 1.0.0 的 create/edit/check/export 与备注导出。agent 读 slides.md 构建 PPTD，不自研 Markdown 转换器。激活或调用失败如实报告；确认不可用后再说明安装或可用的替代路径。

图片元素本身必须按原图比例设置框，不仅依赖 contain 选项。外部渲染预览曾出现缩放/裁切异常，需用独立查看器复核，不能为迎合错误预览反向扭曲 PPT 几何。slides 是内容源，PPTD/PPTX 单向派生，视觉微调不双向同步。

## 7. 安装、开发与发布

### 安装说明

正式桌面安装见 README；CLI 等价命令为 `dsh plugin add dsh-journal-club@0.0.1`。Git 源码安装备选为 `dsh plugin add git+https://github.com/zhang-bin-98/dsh-journal-club.git`，跟随远端 main；prepare 自动构建。非默认 profile 在 `dsh plugin` 后加 `--profile <名称>`，若安装器阻止构建脚本，只按提示批准具体依赖。

本地开发安装执行 `npm ci` 后 `dsh plugin add .`，npm ci 会运行 prepare 构建；更新后完整重启宿主并重新调用 skill，已注入历史会话的文本不会自动改写。完整流程配置 `MINERU_TOKEN` 或复用已有 CLI token 配置即可，无需全局安装 MinerU CLI/Python PDF 引擎；PPTX 另装 dsh-ppt-maker。

包遵循官方 [bundle 发布规范](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.md) 和 [client 模块契约](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/modules/README.md)：声明 `dsh.bundle.patch`、`engines.dsh` 与 web client 入口；共享宿主实例的依赖同时列在 peerDependencies/devDependencies。npm 包和 Release tgz 携带预编译 host/client/Remote、MinerU runner 及运行时 skill，安装不要求构建源码。

插件显示信息按官方 [元数据约定](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-a-package.md#plugin-display-metadata) 随包导出 `locale/en.json`、`locale/zh.json`，提供名称与简介；这些是 UI 资源，不增加英文文档。图标与独立详情页可选，当前使用默认图标和包内中文 README。发布到 npm 后可按包名安装；进入「发现」列表还需要 [插件索引源](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/plugin-market.md)，不随 npm 发布自动上架。

### 本地检查

```sh
npm ci
npm run fixtures:fetch
npm run typecheck
npm test
npm run verify:pack
```

test 前置步骤构建 host/client/Remote；verify:pack 重新构建并检查实际安装包，内部 pack 跳过重复生命周期脚本。固定论文按 manifest URL 与 SHA-256 下载，已存在且正确即复用；常规回归不消费 MinerU 或模型配额。来源与许可见 [fixture 说明](../../tests/fixtures/papers/README.md)。解析几何 fixture 保留数值与块类型、正文为合成文本，不代表真实全文回归。

`out/` 和本地 `docs/verification/` 保持忽略；真实论文、解析全文和验收产物不进入 Git 或安装包，密钥不进入文件示例与日志。包检查覆盖 host/client/Remote、运行时 skill、MIT、中文 README 与横幅，以及 DSH bundle/client 声明、入口和类型导出、中英文显示信息及其资源导出。文档变更检查链接与契约一致性；行为变更运行对应回归，真实模型与桌面验证单独说明。

### 分支与发布

- `main` 是唯一推送 origin 的长期分支；`develop` 仅本地开发，不跟踪或推送远端。专项任务从 develop 建临时 `codex/<topic>`，完成后合回并删除。
- 合回 develop 和发布合入 main 都用 `--no-ff` 保留拓扑，不 squash/rebase；验收及用户审核后才合并发布。不要使用 push --all/--mirror。
- CI 在 main push、面向 main 的 PR 和手动触发时运行 Windows/Linux 检查：锁定依赖、fixture、类型检查、回归、安装包和工作树变更检查，不需要模型密钥。
- 更新 package.json/锁文件版本并通过审核合入 main 后，显式推送匹配的 vX.Y.Z 标签。Release 工作流校验 main 历史归属与版本，再检查并产出带 SHA-256 的 **草稿 Release**；普通 push 不发布。
- 维护者检查草稿安装包后发布 GitHub Release，npm-publish 工作流下载同一 tgz/sha256，校验标签、哈希、包名/版本/许可/仓库元数据后原包上传，不重新构建。正式版用 latest；版本含预发布后缀或 GitHub prerelease 用 next。
- 首次 npm 发布需仓库 Actions secret `NPM_TOKEN`，具备该包自动发布权限；缺失会明确失败。GitHub 打包使用自带 GITHUB_TOKEN，不依赖 npm key。配置修正后可重跑失败工作流，已发布版本不能覆盖。

公开仓库为 `zhang-bin-98/dsh-journal-club`，软件和原创文档使用 MIT；GitHub 默认 main，仅启用 merge commit 合并。建议 Topics：dsh-plugin、deepseek-harness、journal-club、biomedical-research、scientific-presentations。外部贡献通过 fork 向 main 提交 PR。
