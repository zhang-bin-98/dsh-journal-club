## 1. 技术选型

### 1.1 依赖全景（全部现成能力，零自研引擎）

| 能力 | 方案 | 说明 |
|---|---|---|
| PDF 解析（文本/阅读顺序/表格/图注/整图 bbox/LaTeX） | **官方 `mineru-open-api` CLI**（`npm i -g mineru-open-api`，OpenDataLab 官方维护） | **两档模式**：高精度分别执行 `extract main.pdf -f md -o parse/main/` 与 `extract main.pdf -f json -o parse/main/`（复用已有产物；组合格式实测差异见 [D21](../decisions.md#d21-独立论文工作区与真实解析格式2026-10-29)）（需注册 mineru.net + 控制台 API Key，`auth` 命令或 `MINERU_TOKEN` 一次性配置——完整流程的默认与推荐档）；免费 `flash-extract`（免 token，≤10MB/20 页，**仅 Markdown 无结构化输出**——整图定位退化为 agent 视觉，skill 引导时明示差异，定位为试用）。长文用 dsh bash `run_in_background`；**缓存按 `parse/manifest.json` 精确命中**（见 4.2，防不完整/过期/换模式误复用）。自建端点不支持——README 将 dsh-pdf-mineru 列为隐私敏感备选。**M1 实测（v0.5.9）**：json 即 content-list（block 数组，image/chart 块含整图 bbox、img_path、image_caption）；images/ 随包落盘；**bbox 为两轴各自 0–1000 归一化坐标**，换算 `pt = norm/1000 × 旋转后页面尺寸`（换算已固化为 `src/pdf/mineru.ts`，见 §1.2） |
| 整页渲染 PNG、按 bbox 裁切 | **pdfjs-dist + @napi-rs/canvas**（Node，预编译零系统依赖） | 裁切用裁剪 viewport 从 PDF 重渲染（无损，不用压缩预览图） |
| 拼图组合 | **sharp**（libvips 预编译） | 布局计算纯 TS，贴图 sharp composite；产物登记 groups.json（见 4.2） |
| Panel 切分、标签识别、切分核对 | **agent 多模态视觉**（harness 托管） | 见 1.2；本地零 OCR、零 OpenCV |
| figures.json 写入通道 | **`update_figures` 工具**（本插件第 5 个原子工具） | json-patch + base-rev 乐观锁 + 原子替换 + 写前滚动快照；工作台（经 host RPC）与 agent 共用，防双写者覆盖（见 §3/§5） |
| LLM / 会话 / 文件 / 权限 / 预览 | dsh harness | 产品设计已定 |

运行环境：Node ≥ 22（与 dsh 一致）+ 全局 `mineru-open-api` + MinerU token。skill 内嵌 CLI 用法（含 flash/extract 模式选择、输出约定、后台跑法），用户无需安装任何其他 skill 或插件。

### 1.2 切分分工：agent 视觉为主力，crop 是反馈闭环

1. 分别执行 `mineru-open-api extract main.pdf -f md` 与 `mineru-open-api extract main.pdf -f json` → `parse/` 落盘并登记 manifest；json（content-list）的 figure 块给出**整图 bbox**（agent 不用自己找整图）。**M1 实测：bbox 为两轴各自 0–1000 归一化，写入 figures.json 前经 `src/pdf/mineru.ts` 换算为 PDF pt（旋转后基准）；个别复杂大图的整图框可能偏小（实测 3/4 图页精确、1 页部分覆盖），agent 视觉切分与工作台手调兜底正是为此设计**。
2. agent 看 `render_pages` 高清页图 + 整图 bbox → **视觉切分 panel**：经 `update_figures` 写入 figures.json（regions + panels 粗框 + 标签）。
3. `crop` 裁出 Panel PNG → agent（和用户）看裁切结果验证；不准则改 bbox 重裁——**迭代闭环**替代本地几何算法。
4. 图源核对工作台手调是最终兜底。

不做本地 OCR / 连通域几何：位图标签、无文本层 PDF 一律 agent 视觉处理；确不可判定的标疑点（产品规则不变）。

### 1.4 坐标规范（继承 SmartJC）

bbox 统一 PDF 点（pt）、原页旋转后基准；持久化坐标与显示缩放无关；最终裁切从 PDF 重渲染。人工调框与新增 Panel 以真实页尺寸为边界；超出初始 region 时，在同次 update_figures/CAS patch 中扩展 region 包含新框，保留 Panel 必须位于 region 内的契约，不修改其他 Panel。**MinerU content-list bbox 与 pdfjs 渲染坐标的对齐**（旋转页尤甚）是 M1 验收项，映射在 skill 编排与 figures.json 写入时规整。

## 3. 工具契约（5 个原子工具）

所有工具：相对路径基于会话工作目录；返回 `ToolResult`（文本摘要 + 结构化落盘）；支持 `run_in_background` 与 `AbortSignal`。

| 工具 | 输入（zod） | 输出/副作用 |
|---|---|---|
| render_pages | `{ path, pages: number[], dpi?: 150\|300 }` | 写 `pages/<doc>-<NNN>.png`；返回路径列表 |
| crop | `{ figures_json, ids?: string[]（默认全部已采纳）, dpi?: 300 }` | 按 bbox 裁剪 viewport 渲染 → `figures/<panel_id>.png`；新 asset 路径经 update_figures 一次回写（一次裁切至多 revision+1），已有 asset 仅在 revision 未变时替换像素；异常项（越界/空框等）列入 anomalies 不阻断其余 panel，返回清单只含实际落盘的资产 |
| compose_panels | `{ assets: string[], layout_hint?, geometry?, scale?, output, create?: false }` | 建议排版（候选+评分，缩自 SmartJC 图组算法）或任意尺寸自由几何，不设图片数量上限 → `groups/<name>.png` + **登记/更新 groups.json 条目**（成员、输入指纹、布局几何）；默认按既有 asset 更新并保留原 ID，未登记 output 拒绝；只有明确新建用 create:true，拒绝覆盖已有路径/ID。返回预览路径与布局说明 |
| update_figures | `{ figures_json, patch: json-patch[], base_rev }` | **figures.json 唯一写入通道**：缺文件且 base_rev=0 时以空初值应用 patch，校验至少一份 document，成功 revision=1、无旧版快照；已有文件校验 base_rev（不匹配返回冲突）→ 应用 patch → 写前留滚动快照 → 原子替换。rev 单调递增，每次成功写 +1。agent 与工作台共用；用户手动编辑文件允许（下次写入遇 rev 冲突提示重载） |
| validate | `{ project_dir }` | 读 deck.md/outline.md/figures.json/groups.json → `{errors[], warnings[]}`；figures.json 跨字段规则与 update_figures 写入前校验同源（违例统一为 `FIGURES_INVALID`）；stdout 摘要 |

首次初始化的内存初值为 `{version:1,status:"draft",revision:0,documents:[],figures:[]}`；可 add 文档/图数组项或 add 根路径完整初值，根对象 revision 必须为 0。失败不留下主文件；并发初始化与后续编辑共用锁/CAS。`history_path` 仅有旧文件时返回。

figures.json 的语义内容（切什么、怎么改）由 agent/用户决定——文件即真相 + agent 信任不变；`update_figures` 只是**写入通道与完整性保护**（防双写者 lost update、可回滚），不是审批流程。MinerU 编排同理：CLI 解析落盘 parse/，agent 读 content-list 经 update_figures 写整图 regions。

## 4. 数据契约

### 4.1 figures.json（核心，v1 schema）

```jsonc
{
  "version": 1,
  "status": "draft",            // draft | confirmed
  "revision": 3,                // 每次经 update_figures 成功写入 +1（不分是否已确认）；确认记录绑定此值，下游失效判定用
  "documents": [
    { "id": "main", "path": "main.pdf", "role": "main", "pages": 38 },
    { "id": "supp", "path": "supplement.pdf", "role": "supplement", "pages": 24 }
  ],
  "figures": [{
    "id": "fig1",                       // 稳定 ID，文件名基础
    "label": "Figure 1",                // 原文图号；未标号可空
    "status": "pending",                // pending | viewed | adjusted | excluded
    "regions": [                        // 图块：单页 1 个 region（跨页多 region，v1 不拼接）
      { "document": "main", "page": 6, "bbox": [x0, y0, x1, y1] }   // pt，原页旋转后基准
    ],
    "caption": { "page": 6, "sentences": ["…", "…"] }, // page 为图注起始物理页；核实的续页图注也进入 sentences
    "panels": [{
      "id": "fig1_A",                   // = asset 文件名主干（deck.md 引用锚点）
      "label": "A",
      "region_index": 0,
      "bbox": [x0, y0, x1, y1],
      "asset": "figures/fig1_A.png",    // crop 后回填；草稿期可空
      "caption_refs": [0, 3],           // caption.sentences 索引（多对多）
      "flags": [],                      // overlap | no-label | edge-cut | cross-page | missing-caption
      "origin": "auto"                  // auto（MinerU 整图）| manual（工作台）| agent（视觉切分）
    }]
  }]
}
```

规则：panel `id` 全局唯一且**永不复用**；`origin` 非 auto 的 panel 不被后续 agent 重切静默覆盖（skill 软约定 + 工作台不覆写标记）；每次成功写入 `revision+1`；确认后的任何写入都使图源确认失效（revision 不再匹配），下游引用旧 revision 时 validate 给 warning。**whole-Panel 归一化**：无 Panel 的单图（整图直接采纳）表示为唯一一个 `label: null` 的 panel，bbox = region bbox——数据与裁切无特判，deck.md 引用方式与普通 panel 一致。若原字母 Panel 的必要标注交错、矩形无法独立保全，则保留这些身份和疑点，另加同一 region 的 whole-Panel 供整图兜底引用；不将兜底计作独立切分成功，不新增数据字段。写入一律经 `update_figures`（rev 乐观锁）。

### 4.2 其余契约文件

- `jc.md`：见 [对话入口](../product/对话入口.md) §5（frontmatter 含 **confirmations 段**——每个确认点记录内容摘要/revision 与时间；恢复时以 digest 比对判定确认是否仍有效）。
- `groups.json`：完整项目初始化时若不存在，创建 `{ "version": 1, "groups": [] }`，无拼图也可计算确认摘要；不覆盖已有清单。**图组清单（组合图的机器可读来源契约）**：

```jsonc
{
  "version": 1,
  "groups": [{
    "id": "fig4_AD",                       // = groups/<id>.png 文件名主干
    "asset": "groups/fig4_AD.png",
    "members": ["fig4_A", "fig4_B", "fig4_C", "fig4_D"],   // panel id 引用
    "inputs_digest": "sha256:…",           // 成员 panel 资产内容指纹（重裁后不匹配→提醒重建）
    "layout": { "kind": "manual", "geometry": { "width": 900, "height": 700, "gap": 12, "cells": [{ "member": "fig4_A", "x": 10, "y": 20, "width": 300, "height": 200 }] } } // 简略示意；实际 cells 与 members 一一对应
  }]
}
```

`layout.geometry` 为普通文件中的布局真相：正导出尺寸与有限数值图片包围框，`cells` 不得重复或遗漏成员；`content` 是 contain 的可重算派生值。`kind` 支持 manual/grid/rows/1+2；旧版布局可直接打开。手调保留包围框，源图片比例变化时重新等比适配，不重排；UI 与 sharp 共用 fit/像素取整。显式几何输入的 width/height 为参考尺寸，不作裁切边界；UI 与工具先 contain 再取实际图片外接矩形，平移到原点并记录派生的导出宽高，去掉外围空白，保留内部间隔与原图内容。不限制比例、图片数量；无几何仍使用建议排版。编辑视图另留余量，按需扩展，不写入文件。图片按 cells 顺序绘制，并以该顺序登记 members 与输入指纹。

validate 将 deck.md 中的 group 引用**展开为成员 panel** 检查身份与存在性；inputs_digest 不匹配（成员被重裁）→ warning 提醒重建拼图；deck 确认记录包含 groups digest（拼图变更使确认点 3 失效）。

- `parse/`：MinerU 产物存档（markdown、content-list、images、layout），根部 `parse/manifest.json` 为**缓存清单**：

```jsonc
{
  "documents": [{
    "id": "main", "source_sha256": "…", "mode": "extract",   // extract | flash
    "cli_version": "x.y.z", "artifacts": ["md", "content-list", "images"],
    "status": "done"                                          // done | partial（中断/失败）
  }]
}
```

缓存命中条件：源摘要 + 模式 + status=done + 产物齐全四条全中——防止补入补充材料、解析中断残留、免费→高精度切换时误复用；partial 结果保留用于断点续传但不视为成功。analysis.md 生成的证据底料即此目录，agent 按需分页读取；**paper.json 不再是必需产物**（agent 直读 content-list；若 M3 发现上下文开销大，再补轻量聚合工具——待定项）。
- `analysis.md` / `outline.md` / `deck.md`：人读契约，格式见 [deck 格式](../product/deck格式.md) 与产品设计 4.6；validate 只解析 deck.md 固定标记（页头注释/来源行/讲稿块），**发现覆盖等语义检查归 agent**（skill 剧本：确认前对照 analysis.md 发现清单自查）。

## 5. UI 结构要点

- **技术底座（零新增）**：React 由宿主提供（peer，client 插件渲染进宿主 React 树）；状态 = React hooks + 文件 watch 轻 store，不引状态库；样式 = `jc-` 前缀类名的 TS 内联样式表（`styles.ts` 注入一次 `<style>`）+ `--dsh-alias-*` 语义 token（明暗主题自动跟随）+ `ui-primitives` 共享控件；不引任何 CSS 框架（不用 CSS Modules 的原因见决策 D18）。
- **JC tab**（`ctx.sidebarRightTabs.register`）：三态——空态（引导 + 轻发现 jc.md 项目）/ 状态卡（读 jc.md + 产物实况）/ 核对工作台（读 figures.json，fs watch 自动刷新，最近变更高亮）。
- **核对工作台**：Figure 连续列表；单图编辑按容器宽度使用左画布/右预览属性两栏或窄区单栏，单行 Panel 导航、顶部编辑工具与限高滚动区避免长图注挤走操作（见 [图源核对 §3](../product/图源核对.md#3-工作台figure-连续核对列表)）。页图底图 + 框叠加，pt→显示坐标按 host 返回的真实 PDF 页宽高换算；四角手柄、裁切预览（从 pages 底图裁显示；正式资产仍由 crop 从 PDF 重裁）、图注高亮（caption_refs）、放大编辑（复用同一组件的原生 dialog）。写路径：**UI 编辑 → host RPC 调 `update_figures`**（dsh `workspaceFiles` 为只读服务，client 不能直写；host 侧 service 是唯一落盘通道，与 agent 同一乐观锁协议——UI 与 agent 的并发修改互不覆盖，冲突时提示重载）。改框类编辑成功后再经 host RPC `cropPanels` 调用与 crop 工具同一实现重裁对应 Panel，保持 agent 读取的资产与工作台一致（D34）。
- **自由拼图**：JC tab 切换入口，左侧滚轮直接切组的缩略图窄栏、主画布 + 可收起「素材 / 属性」标签栏，素材默认显示按 Figure 分组的等比缩略图；IntersectionObserver 延迟文件读取，原生 dialog 查看大图，复用现有文件缓存。窄区上下布局与原生放大 dialog；默认适应模式从当前图片外缘派生 viewBox，手势期间冻结坐标、结束后自动取景，SVG 像素高度与视图比例一致并清除旧滚动偏移，手动放大仍可滚动；图组草稿只存当前组件，切组/放大不丢失，显式保存写普通文件。`compositionState` 读取清单摘要和 Panel 尺寸/内容摘要，`saveComposition` 调与工具共享的 `composePanels`。「刷新图源」重读素材并清除文件缓存，只替换各草稿的 inputs，保留几何、撤销历史及 groups CAS base；读取成功后复用保存函数自动组合当前图组，冲突或素材缺失时保留草稿并报错，不批量重建。原图仍由原工作台 `update_figures` → `crop` 调整，不新增工具耦合或自动级联重建。compositionState 复用 parseDeck，按 deck.md 首次图片引用派生 order；无文稿时沿用清单顺序，存在文稿时不显示未引用旧图，缺失 PNG 不列入。当前会话新建图组暂留末尾；文稿/清单移除的旧图连同旧草稿退出列表，不写额外排序文件。宿主 workspaceFiles.changes 监听 groups.json、deck.md 与 groups 目录，通知后重读清单并更新没有未保存调整的图组及缩略图；保留当前选中项，脏草稿保留历史和 CAS base，沿用显式重载入口。保存或拖动期间延后处理通知。UI/工具均原位更新已有清单条目，新图组才追加。host 修改按原 ID 查登记的 asset，不重新推导文件名；工具在清单锁内以 output 匹配原条目并保留其 ID，只有 create:true 可新建，且不能覆盖已有条目或文件。不新增别名表或按成员自动去重。保存于 groups 文件锁内检查 base_digest 和图源摘要；渲染后再检查输入，过期则保留草稿并提示重新加载，不强制覆盖。「加入对话」接收宿主通过 Session 标准 props 提供的 inputActions，保存前捕获输入位置/版本，保存后插入原生文件引用；不调用 conversation.send，不自行保存对话上下文。工具仍为五个，不新增流程工具或客户端存储库。
- **聊天轻卡片**（ConversationNode）：图源卡（摘要 + 打开工作台 + 快捷确认）、outline/deck 确认卡；按钮先取 `sessions.scope(sessionId)`，再由 `scope.get('conversation').send(text)` 回流标准指令文本（`/jc confirm figures` 等——指令即文本，无隐藏协议）。借用的会话 Context 不继承插件注入声明，使用宿主相同的 get 访问方式；会话或服务不可用时显示错误，见 D22。

**宿主接口落实**：`JournalClubService` 继承官方 `TypertRemoteService`，Remote 方法声明 sessionId 资源访问；由宿主当前会话解析 cwd，文件先检查词法范围，再 realpath 检查符号链接目标。图源工作台只允许经同一个 updateFigures 服务修改 figures.json，完成 CAS 与快照；自由拼图仅经 compose 服务更新项目内 groups.json 和组合 PNG；`cropPanels` 同样限定会话内 figures.json，复用 crop 工具的 `cropFigures`。`pageInfo` 从原始 PDF 返回旋转后的真实尺寸与页图路径。官方 Typert 生成器输出 `./typert` 与 `./remote`，不手写 wire descriptors；独立包构建适配见 D19。

**文件与入口**：workspaceFiles 按分页读取完整文本；项目发现扫描 cwd 与一级子目录的 jc.md，选中项目后读取其文件，多个候选不擅自指定。卡片由 `<!-- jc-card {"project":"论文目录","stage":"figures"} -->` 标记生成，stage 为 figures/outline/deck；按钮发送带项目路径的标准文本或打开宿主预览。标记不存状态、不代表确认；确认与恢复仍由 skill 检查文件决定。

## 6. skill 剧本骨架（skills/journal-club/SKILL.md）

随包交付 `references/formats.md`、`references/narrative.md` 与 `references/research/*.md`；注册内容提供安装路径及 `lib/project.js` helper 路径，helper 通过 `dsh-journal-club/project` 导出。不要求安装用户访问源码仓库 docs。

1. 触发与分流（完整流程 / 局部任务 / 恢复；边界判断：原创研究；检测 `mineru-open-api` 可用与 token，给安装/注册引导）
2. 步骤 1 论文分析：检查 token——未配置发注册引导（mineru.net 注册 → 控制台 API Key → `auth` 配置），拒绝注册时明示差异降级 flash-extract 试用 → 宿主命令分别执行 `mineru-open-api extract main.pdf -f md -o parse/main/` 与 `mineru-open-api extract main.pdf -f json -o parse/main/`（后台；**缓存按 parse/manifest.json 四条件命中，不完整/换模式/换文档不复用**）→ 读 content-list → 建 jc.md / figures.json（整图 regions + captions 归组，经 update_figures）→ `render_pages`（figure 页 + 疑点页）→ **agent 视觉切 panel**（经 update_figures 写粗框与标签）→ `crop` → agent 看裁切结果迭代粗框 → analysis.md 生成规则（发现覆盖、引用块+页码、疑点标记）
3. 确认点 1：引导右侧栏工作台；确认 = `/jc confirm figures` → crop 全量（兜底工作台未刷新的重裁）→ 读取裁切后的 revision 定稿 → 写 jc.md confirmations（revision）
4. 步骤 2 outline.md：叙事策略（继承 SmartJC 五策略）、主线/补充、内嵌图引用规范
5. 确认点 2：`/jc confirm outline` → 写 jc.md confirmations（outline digest）
6. 步骤 3 deck.md：分页规则、compose_panels 编排（何时拼图、layout 提示、groups.json 登记）、validate 通过才算完成
7. 确认点 3：`/jc confirm deck` → 写 jc.md confirmations（deck digest + groups digest）→ PPTX 编排（先调用已安装的 ppt-maker skill 激活工具 → 检查实际 ppt_* 工具/schema → 调用序列 → 讲者备注 → 质检导出；备选路径）。初始工具列表缺少 ppt_* 不等同未安装；激活失败按实际错误处理，见 [D20](../decisions.md#d20-ppt-工具懒加载2026-10-29)。

9. 恢复语义：读 jc.md + 产物实况，按断点续跑；**确认有效性按 digest 比对**（confirmations 记录 vs 当前文件/图组内容），不一致或无记录时**停在该确认点等用户**，不自行推进
