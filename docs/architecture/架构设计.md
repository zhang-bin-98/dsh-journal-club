## 1. 技术选型

### 1.1 依赖全景（全部现成能力，零自研引擎）

| 能力 | 方案 | 说明 |
|---|---|---|
| PDF 解析（文本/阅读顺序/表格/图注/整图 bbox/LaTeX） | **官方 MinerU API + 随包 Node runner**（`lib/mineru.js`） | 一次高精度任务返回 Markdown、content-list 和图片；无全局 CLI 依赖。API token 读环境变量或既有 CLI 配置；flash 为免 token 的受限试用。超时、重试、任务恢复与缓存契约见 §6.1。解析算法仍在官方服务，bbox 两轴各自 0–1000 归一化；原 `src/pdf/mineru.ts` 坐标换算继续复用 |
| 整页渲染 PNG、按 bbox 裁切 | **pdfjs-dist + @napi-rs/canvas**（Node，预编译零系统依赖） | 裁切用裁剪 viewport 从 PDF 重渲染（无损，不用压缩预览图）；启动时也用 `render_pages` 渲染第 1 页，由 agent 读图识别标题/类型，总页数取返回的 `num_pages`。默认不为身份识别或元数据加载、探测 Python PDF 引擎 |
| 拼图组合 | **sharp**（libvips 预编译） | 布局计算纯 TS，贴图 sharp composite；产物登记 groups.json（见 4.2） |
| Panel 切分、标签识别、切分核对 | **agent 多模态视觉**（harness 托管） | 见 1.2；本地零 OCR、零 OpenCV |
| figures.json 写入通道 | **`update_figures` 工具**（本插件第 5 个原子工具） | json-patch + base-rev 乐观锁 + 原子替换 + 写前滚动快照；工作台（经 host RPC）与 agent 共用，防双写者覆盖（见 §3/§5） |
| LLM / 会话 / 文件 / 权限 / 预览 | dsh harness | 产品设计已定 |

运行环境：Node ≥ 22.13（与 dsh 一致）+ MinerU token。随包 runner 直接访问官方 API，ZIP 流式解包复用 yauzl，配置解析复用 yaml；无需额外 CLI、Python 或新 DSH 工具。

### 1.2 切分分工：agent 视觉为主力，crop 是反馈闭环

1. 调用随包 runner：`node "<runner>" main.pdf --output parse --id main`，补充材料以 `--id supp` 单独处理。一次提交、轮询、下载 ZIP，检查产物后保存 manifest；content-list 给出整图 bbox，坐标按同一 helper 换算。传输失败不说明文档不可解析，恢复细则见 §6.1。
2. agent 看 `render_pages` 高清页图 + 整图 bbox → **视觉切分 panel**：经 `update_figures` 写入 figures.json（regions + panels 粗框 + 标签）。
3. `crop` 裁出 Panel PNG → agent（和用户）看裁切结果验证；不准则改 bbox 重裁——**迭代闭环**替代本地几何算法。
4. 图源核对工作台手调是最终兜底。

不做本地 OCR / 连通域几何：位图标签、无文本层 PDF 一律 agent 视觉处理；确不可判定的标疑点（产品规则不变）。

### 1.4 坐标规范（继承 SmartJC）

bbox 统一 PDF 点（pt）、原页旋转后基准；持久化坐标与显示缩放无关；最终裁切从 PDF 重渲染。人工调框与新增 Panel 以真实页尺寸为边界；超出初始 region 时，在同次 update_figures/CAS patch 中扩展 region 包含新框，保留 Panel 必须位于 region 内的契约，不修改其他 Panel。**MinerU content-list bbox 与 pdfjs 渲染坐标的对齐**（旋转页尤甚）是 M1 验收项，映射在 skill 编排与 figures.json 写入时规整。

## 3. 工具契约（5 个原子工具）

所有工具：相对路径基于会话工作目录；返回 `ToolResult`（文本摘要 + 结构化落盘）；支持 `run_in_background` 与 `AbortSignal`。

| 工具 | 输入（zod） | 输出/副作用 |
|---|---|---|
| render_pages | `{ path, pages: number[], dpi?: 150\|300 }` | 写 `pages/<doc>-<NNN>.png`；返回路径列表 |
| crop | `{ figures_json, ids?: string[]（默认全部已采纳）, dpi?: 300 }` | 按 bbox 裁剪 viewport 渲染 → `figures/<panel_id>.png`；在 figures.json 锁内确认 revision 未变后替换像素并把新 asset 路径一次回写（一次裁切至多 revision+1）；异常项（越界/空框等）列入 anomalies 不阻断其余 panel，返回清单只含实际落盘的资产 |
| compose_panels | `{ assets: string[], layout_hint?, geometry?, scale?: 2, output, create?: false }` | 建议排版（候选+评分，缩自 SmartJC 图组算法）或任意尺寸自由几何，不设图片数量上限 → `groups/<name>.png` + **登记/更新 groups.json 条目**（成员、输入指纹、布局几何）；默认按既有 asset 更新并保留原 ID，未登记 output 拒绝；只有明确新建用 create:true，拒绝覆盖已有路径/ID。返回预览路径与布局说明 |
| update_figures | `{ figures_json, patch: json-patch[], base_rev }` | **figures.json 唯一写入通道**：缺文件且 base_rev=0 时以空初值应用 patch，校验至少一份 document，成功 revision=1、无旧版快照；已有文件校验 base_rev（不匹配返回冲突）→ 应用 patch → 写前留滚动快照 → 原子替换。rev 单调递增，每次成功写 +1。agent 与工作台共用；用户手动编辑文件允许（下次写入遇 rev 冲突提示重载） |
| validate | `{ project_dir }` | 读 slides.md/outline.md/figures.json/groups.json → `{errors[], warnings[]}`；figures.json 跨字段规则与 update_figures 写入前校验同源（违例统一为 `FIGURES_INVALID`）；stdout 摘要 |

首次初始化的内存初值为 `{version:1,status:"draft",revision:0,documents:[],figures:[]}`；可 add 文档/图数组项或 add 根路径完整初值，根对象 revision 必须为 0。失败不留下主文件；并发初始化与后续编辑共用锁/CAS。`history_path` 仅有旧文件时返回。

figures.json 的语义内容（切什么、怎么改）由 agent/用户决定——文件即真相 + agent 信任不变；`update_figures` 只是**写入通道与完整性保护**（防双写者 lost update、可回滚），不是审批流程。MinerU 编排同理：随包 API runner 将官方结果落盘 parse/，agent 读 content-list 经 update_figures 写整图 regions。

图像执行同样复用插件：agent 读 `render_pages` 页图作视觉判断，`update_figures` 写框，`crop` 从 PDF 刷新 Panel，`compose_panels` 生成组合 PNG 并登记来源；不以 Python/Pillow/NumPy 脚本替代裁切、拼图，或自建空白带/阈值/轮廓分割算法。工作台通过现有 `pageInfo`、`updateFigures`、`cropPanels`、`compositionState`、`saveComposition` Remote 复用同一核心；这些是会话作用域 UI 接口，不是另增的模型工具。agent 暂无坐标标尺/批量核对图接口，常规核对使用实际资产和工作台，不将临时联系图登记成汇报图组。此边界不限制 PPT/PPTX 的生成或兼容性排错。

## 4. 数据契约

### 4.1 figures.json（核心，v1 schema）

```jsonc
{
  "version": 1,
  "status": "draft",            // draft | confirmed
  "revision": 3,                // 每次经 update_figures 成功写入 +1（不分是否已确认）；确认记录绑定此值，下游失效判定用
  "documents": [
    { "id": "main", "path": "main.pdf", "role": "main", "pages": 38 },
    { "id": "supp", "path": "supplement.pdf", "role": "supplement", "pages": 24 }
  ],
  "figures": [{
    "id": "fig1",                       // 稳定 ID，文件名基础
    "label": "Figure 1",                // 原文图号；未标号可空
    "status": "pending",                // pending | viewed | adjusted | excluded
    "regions": [                        // 图块：单页 1 个 region（跨页多 region，v1 不拼接）
      { "document": "main", "page": 6, "bbox": [x0, y0, x1, y1] }   // pt，原页旋转后基准
    ],
    "caption": { "page": 6, "sentences": ["…", "…"] }, // page 为图注起始物理页；核实的续页图注也进入 sentences
    "panels": [{
      "id": "fig1_A",                   // = asset 文件名主干（slides.md 引用锚点）
      "label": "A",
      "region_index": 0,
      "bbox": [x0, y0, x1, y1],
      "asset": "figures/fig1_A.png",    // crop 后回填；草稿期可空
      "caption_refs": [0, 3],           // caption.sentences 索引（多对多）
      "flags": [],                      // overlap | no-label | edge-cut | cross-page | missing-caption
      "origin": "auto"                  // auto（MinerU 整图）| manual（工作台）| agent（视觉切分）
    }]
  }]
}
```

规则：panel `id` 全局唯一且**永不复用**；`origin` 非 auto 的 panel 不被后续 agent 重切静默覆盖（skill 软约定 + 工作台不覆写标记）；每次成功写入 `revision+1`；确认后的任何写入都使图源确认失效（revision 不再匹配），下游引用旧 revision 时 validate 给 warning。**whole-Panel 归一化**：无 Panel 的单图（整图直接采纳）表示为唯一一个 `label: null` 的 panel，bbox = region bbox——数据与裁切无特判，slides.md 引用方式与普通 panel 一致。若原字母 Panel 的必要标注交错、矩形无法独立保全，则保留这些身份和疑点，另加同一 region 的 whole-Panel 供整图兜底引用；不将兜底计作独立切分成功，不新增数据字段。写入一律经 `update_figures`（rev 乐观锁）。

### 4.2 其余契约文件

- `jc.md`：见 [对话入口](../product/对话入口.md) §5（frontmatter 含 **confirmations 段**——每个确认点记录内容摘要/revision 与时间；恢复时以 digest 比对判定确认是否仍有效）。
- `groups.json`：完整项目初始化时若不存在，创建 `{ "version": 1, "groups": [] }`，无拼图也可计算确认摘要；不覆盖已有清单。**图组清单（组合图的机器可读来源契约）**：

```jsonc
{
  "version": 1,
  "groups": [{
    "id": "fig4_AD",                       // = groups/<id>.png 文件名主干
    "asset": "groups/fig4_AD.png",
    "members": ["fig4_A", "fig4_B", "fig4_C", "fig4_D"],   // panel id 引用
    "inputs_digest": "sha256:…",           // 成员 panel 资产内容指纹（重裁后不匹配→提醒重建）
    "layout": { "kind": "manual", "geometry": { "width": 900, "height": 700, "cells": [{ "member": "fig4_A", "x": 10, "y": 20, "width": 300, "height": 200 }] } } // 简略示意；实际 cells 与 members 一一对应
  }]
}
```

`layout.geometry` 为普通文件中的布局真相：正导出尺寸与有限数值图片包围框，`cells` 不得重复或遗漏成员；图片在包围框内的 contain 位置每次按当前图源重算，不写入文件。`kind` 支持 manual/grid/rows/1+2；旧版布局可直接打开，其中已废弃的 `gap` 与 `cell.content` 读取时忽略、保存时不再写出（自动排版的分区间距只是建议排版内部常量）。手调保留包围框，源图片比例变化时重新等比适配，不重排；UI 与 sharp 共用 fit/像素取整。显式几何输入的 width/height 为参考尺寸，不作裁切边界；UI 与工具先 contain 再取实际图片外接矩形，平移到原点并记录派生的导出宽高，去掉外围空白，保留内部间隔与原图内容。不限制比例、图片数量；无几何仍使用建议排版。工具与工作台默认均按 2 倍像素导出（`scale` 可改），同一图组经不同入口重导分辨率不变。编辑视图另留余量，按需扩展，不写入文件。图片按 cells 顺序绘制，并以该顺序登记 members 与输入指纹。

validate 将 slides.md 中的 group 引用**展开为成员 panel** 检查身份与存在性；inputs_digest 不匹配（成员被重裁）→ warning 提醒重建拼图；slides 确认记录包含 groups digest（拼图变更使确认点 3 失效）。

- `parse/`：MinerU 产物存档（markdown、content-list、images、layout），根部 `parse/manifest.json` 为**缓存清单**：

```jsonc
{
  "documents": [{
    "id": "main", "source_sha256": "…", "mode": "extract",   // extract | flash
    "provider": "mineru-api", "parser_version": 1,
    "options_digest": "…", "batch_id": "…", "uploaded": true,
    "artifacts": ["main/main.md", "main/main.json", "main/images/example.jpg"],
    "artifact_sha256": { "main/main.md": "…", "main/main.json": "…", "main/images/example.jpg": "…" },
    "status": "done"                                          // done | partial
  }]
}
```

此清单由 runner 维护。artifacts 为相对 parse 根目录的真实文件路径，摘要均为原始字节 SHA-256。flash 使用 task_id、不保存 batch_id，只产 Markdown；完整字段、恢复边界见 §6.1。旧 cli_version 记录保留，agent 可检查并继续读有效旧产物；API 自动缓存只复用同 provider/parser_version、源摘要、模式、参数摘要、done 且所有文件摘要相符的结果。其他文档的记录不会被覆盖。analysis 按需分页读取 content-list，不新增 paper.json。
- `analysis.md` / `outline.md` / `slides.md`：人读契约，格式见 [slides 格式](../product/slides格式.md) 与产品设计 4.6；validate 只解析 slides.md 固定标记（页头注释/来源行/讲稿块），**发现覆盖等语义检查归 agent**（skill 剧本：确认前对照 analysis.md 发现清单及正文主图/标号 Panel 实际入页情况自查，不新增程序审批或覆盖状态字段）。

## 5. UI 结构要点

- **技术底座（零新增）**：React 由宿主提供（peer，client 插件渲染进宿主 React 树）；状态 = React hooks + 文件 watch 轻 store，不引状态库；样式 = `jc-` 前缀类名的 TS 内联样式表（`styles.ts` 注入一次 `<style>`）+ 宿主实测的 `--dsw-alias-*` / `--dsw-font-family` token（明暗主题自动跟随）+ 原生表单控件（尚无经验证的独立 ui-primitives 导入契约，不伪称已复用）；不引任何 CSS 框架（不用 CSS Modules 的原因见决策 D18）。
- **JC tab**：项目短标题/切换 + 概览/图源核对/自由拼图三页；概览调用只读 Remote `projectOverview`，复用现有确认摘要 helper，不复制状态机。`keepMounted: true` 保持宿主页签切换时的草稿；本页视图通过 hidden 保留组件。宿主 `registerCloseHandler` 同步保护关闭，切项目复用同一检查。工具数据仍是原文件，不新增项目数据库。
- **浏览位置**：宿主 navigation.params 不持久化，也没有已验证的通用页面偏好 API。`browseLocation.ts` 仅以 `journal-club.browse.v1.<sessionId>` 本地键保存项目路径及每项目 view/figure/panel/group；不存进度、确认或草稿，存储不可用时仍可操作。显式导航高于记忆，记忆高于基于文件的初始推荐；更新文件不改变所在页面。
- **核对工作台**：Figure 连续列表；单图编辑按容器宽度使用左画布/右预览属性两栏或窄区单栏，单行 Panel 导航、顶部编辑工具与限高滚动区避免长图注挤走操作（见 [图源核对 §3](../product/图源核对.md#3-工作台figure-连续核对列表)）。页图底图 + 框叠加，pt→显示坐标按 host 返回的真实 PDF 页宽高换算；四角手柄、裁切预览（从 pages 底图裁显示；正式资产仍由 crop 从 PDF 重裁）、图注高亮（caption_refs）、放大编辑（复用同一组件的原生 dialog）。写路径：**UI 编辑 → host RPC 调 `update_figures`**（dsh `workspaceFiles` 为只读服务，client 不能直写；host 侧 service 是唯一落盘通道，与 agent 同一乐观锁协议——UI 与 agent 的并发修改互不覆盖，冲突时提示重载）。改框类编辑成功后再经 host RPC `cropPanels` 调用与 crop 工具同一实现重裁对应 Panel，保持 agent 读取的资产与工作台一致（D34）。
- **自由拼图**：JC tab 切换入口，左侧滚轮直接切组的缩略图窄栏、主画布 + 可收起「素材 / 属性」标签栏，素材默认显示按 Figure 分组的等比缩略图；IntersectionObserver 延迟文件读取，原生 dialog 查看大图，复用现有文件缓存。窄区上下布局与原生放大 dialog；默认适应模式从当前图片外缘派生 viewBox，手势期间冻结坐标、结束后自动取景，SVG 像素高度与视图比例一致并清除旧滚动偏移，手动放大仍可滚动；图组草稿只存当前组件，切组/放大/切页面不丢失，显式保存写普通文件。`compositionState` 读取清单摘要和 Panel 尺寸/内容摘要；无 figures.json 时仅从已登记成员恢复规范路径图片，`saveComposition` 调与工具共享的 `composePanels`；两者实现在 `compositionService.ts`，host 只做会话解析。「刷新图源」重读素材并清除文件缓存，只替换各草稿的 inputs，保留几何、撤销历史及 groups CAS base；读取成功后复用保存函数自动组合当前图组，冲突或素材缺失时保留草稿并报错，不批量重建。原图仍由原工作台 `update_figures` → `crop` 调整，不新增工具耦合或自动级联重建。compositionState 复用 parseSlides，按 slides.md 首次图片引用派生 order；无文稿时沿用清单顺序，存在文稿时不显示未引用旧图，缺失 PNG 不列入。当前会话新建图组暂留末尾；文稿/清单移除的旧图连同旧草稿退出列表，不写额外排序文件。宿主 workspaceFiles.changes 监听 groups.json、slides.md 与 groups 目录，通知后重读清单并更新没有未保存调整的图组及缩略图；保留当前选中项，脏草稿保留历史和 CAS base，沿用显式重载入口。保存或拖动期间延后处理通知。UI/工具均原位更新已有清单条目，新图组才追加。host 修改按原 ID 查登记的 asset，不重新推导文件名；工具在清单锁内以 output 匹配原条目并保留其 ID，只有 create:true 可新建，且不能覆盖已有条目或文件。不新增别名表或按成员自动去重。保存于 groups 文件锁内检查 base_digest 和图源摘要；渲染后再检查输入，过期则保留草稿并提示重新加载，不强制覆盖。「加入对话」接收宿主通过 Session 标准 props 提供的 inputActions，保存前捕获输入位置/版本，保存后插入原生文件引用；不调用 conversation.send，不自行保存对话上下文。工具仍为五个，不新增流程工具或客户端存储库。
- **聊天轻卡片**（ConversationNode）：图源卡（摘要 + 打开工作台 + 快捷确认）、outline/slides 确认卡；按钮先取 `sessions.scope(sessionId)`，再由 `scope.get('conversation').send(text)` 回流标准指令文本（`/jc confirm figures` 等——指令即文本，无隐藏协议）。借用的会话 Context 不继承插件注入声明，使用宿主相同的 get 访问方式；会话或服务不可用时显示错误，见 D22。

**宿主接口落实**：`JournalClubService` 继承官方 `TypertRemoteService`，Remote 方法声明 sessionId 资源访问；由宿主当前会话解析 cwd，文件先检查词法范围，再 realpath 检查符号链接目标。图源工作台只允许经同一个 updateFigures 服务修改 figures.json，完成 CAS 与快照；自由拼图仅经 compose 服务更新项目内 groups.json 和组合 PNG；`cropPanels` 同样限定会话内 figures.json，复用 crop 工具的 `cropFigures`。`pageInfo` 从原始 PDF 返回旋转后的真实尺寸与页图路径。官方 Typert 生成器输出 `./typert` 与 `./remote`，不手写 wire descriptors；独立包构建适配见 D19。

**文件与入口**：workspaceFiles 按分页读取完整文本；项目发现扫描 cwd 与一级子目录的 jc.md / figures.json / groups.json，选中项目后读取其文件，多个候选不擅自指定。卡片由 `<!-- jc-card {"project":"论文目录","stage":"figures"} -->` 标记生成，stage 为 figures/outline/slides；按钮发送带项目路径的标准文本或打开宿主预览。标记不存状态、不代表确认；确认与恢复仍由 skill 检查文件决定。

### 6.1 MinerU API runner

- **入口**：skill 注册时获得绝对 `lib/mineru.js` 路径。`node "<runner>" <PDF> --output parse --id main|supp`；`--mode extract|flash`，默认 extract。独立于五个 DSH 工具，逻辑位于 `src/mineru/`，不调用模型。先用 `--help` 检查接口。
- **参数与认证**：高精度默认 model=vlm、language=ch、ocr=false、formula/table=true；支持 `--model vlm|pipeline`、`--pages`、`--language`、`--ocr/--formula/--table true|false`。Token 依次读 `MINERU_TOKEN`、`~/.mineru/config.yaml`，不从命令行接收。flash 不读 token，为 ≤10MB/20 页的受限试用；接口限制以服务实际响应为准。
- **提交与恢复**：官方 `/api/v4/file-urls/batch` 申请上传，PUT 原文件，再以 batch_id 查询 `/extract-results/batch/<id>`；flash 使用 `/api/v1/agent/parse/file` 和 `/parse/<task_id>`。先保存任务标识，再上传；结果下载失败重跑相同命令只查询/下载。源文件或参数变化、显式 `--restart` 才新建任务；失败云端任务不自动重建。POST 响应丢失时可能已提交但无本地 ID，无法保证去重，不自动重试 POST。签名上传链接不落盘，上传中断且云端仍等待文件时须显式 restart。
- **传输**：请求 60 秒、上传/下载 600 秒、轮询 1800 秒，三者独立；参数 `--request-timeout`、`--download-timeout`、`--poll-timeout` 单位为秒。查询/上传/下载对网络失败、429、5xx 最多重试两次，指数退避；其他 4xx 不重试。403 等下载地址失效时重新运行命令，通过任务查询取得新的地址。取消信号传播到请求、流、解包；partial 保留任务，不将半成品发布。接口本身不保证签名下载支持 Range，因此当前不做字节断点续传。
- **文件完整性**：ZIP 流式落盘至临时文件，使用 yauzl 流式解包并校验大小/CRC；拒绝路径穿越、符号链接和重复文件。检查非空 Markdown、content-list 结构及全部图片引用，规范化为 `<id>.md`/`<id>.json`，其余官方资产保留。通过后替换该文档输出目录，再以原子 manifest 写入 done；目录替换失败尝试恢复旧目录，不宣称跨文件事务。缺失或被改写的缓存从已有任务恢复。SHA-256、原子写入与文件锁复用项目已有实现。
- **状态与日志**：manifest 为唯一持久任务与缓存事实，不另建状态库；按文档锁避免重复提交，短时 manifest 锁防主/补并发丢记录。上传/下载 URL 和 token 不落盘、不进日志；API/网络错误只记录阶段与状态码，不打印服务响应正文。PowerShell 在读日志前保存原退出码，脚本成功和产物检查共同作为完成依据。
- **验证边界**：固定响应回归覆盖下载恢复、源/参数变化、缓存篡改、并发主/补、flash、解包与取消；真实 API 和宿主验收分开记录，具体结果见 D42。
