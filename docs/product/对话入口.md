# 对话入口设计（v1）

> 隶属 [产品设计](产品设计.md) 的交互细化。覆盖：完整流程发起、局部任务直达、会话恢复、项目状态文件、skill 与工具的职责分层。

## 1. 入口总览

| 入口 | 用户行为 | agent 行为 | 副作用 |
|---|---|---|---|
| **完整流程** | 拖 PDF 进聊天（或给路径），表达汇报意图（"做 journal club / 准备组会汇报"） | 建项目文件夹、复制 PDF、写 jc.md、启动步骤 1 | 进入四步流程与确认点节奏 |
| **局部任务** | "把这个 PDF 的 figure 切出来 / 重新拼这张图 / 校验 deck.md / 渲染 pptx" | 直接组合原子工具执行，就地输出 | **不建项目文件夹、不进流程、不发流程卡片** |
| **恢复** | "继续 journal club"（新会话，工作目录下有项目） | 读 jc.md + 产物实况，从断点继续 | 无新增 |

意图模糊（拖了 PDF 没说话）时 agent 先问一句：完整汇报准备，还是只要切图/分析？——不猜。

## 2. 完整流程发起

### 2.1 触发

- skill 按请求自动匹配，触发词族：journal club / JC / 组会 / 文献汇报 / 论文汇报准备。
- PDF 来源：聊天附件拖入（dsh attachment）、工作目录内路径。主论文必备；补充材料可发起时一起给，或步骤 2 前说"补充材料是这个"再补（之后补入则 agent 重跑受影响的解析部分）。

### 2.2 首轮交互（不阻塞原则）

0. **前置检查（解析前一次性）**：`mineru-open-api` 已安装且 API Key 已配置（高精度模式）。未配置 → agent 给出注册引导：mineru.net 注册 → 控制台获取 API Key → `mineru-open-api auth`（或设 `MINERU_TOKEN`）。用户暂不注册 → 明示质量差异后可降级免费快速模式试用（仅 Markdown、无结构化输出、≤20 页）。

1. agent 从 PDF 提取论文名，**直接确定**项目文件夹名并建立 `<论文名>/`、复制 PDF、写入 jc.md——不发起名确认（不满意随时说，agent 改名并迁移）。
2. 立即启动步骤 1（论文分析）；**同时异步问一次**："有汇报时长/重点要求吗？没有就按充分覆盖默认来，之后随时可改。"答案写入 jc.md 的 `requirements`，只影响步骤 3 及之后，不阻塞步骤 1。
3. 首轮回复包含：项目路径、四步计划一句话、正在开始步骤 1。

### 2.3 边界拒绝（skill 层，不在工具层）

- 支持**原创研究**的完整流程；Review / Meta-analysis / 指南 / 病例报告 / 非生物医学 → agent 识别后说明完整流程不支持。
- **论文类型门槛只存在于 skill 编排**；原子工具不设论文类型判断——用户对一篇 Review 只要切图，照样可以（工具原子化的自然推论）。
- 扫描件 / 加密 / 损坏 PDF：`parse_pdf` 失败即如实提示更换可解析版本。

## 3. 局部任务直达

工具自描述（描述即用法），agent 无需加载 JC skill 即可组合：

- "把这个 PDF 的图切出来" → `parse_pdf`（图注定位）+ `detect_figures` + `crop`，输出到当前目录 `figures/`。
- "这四张 panel 拼成一页" → `compose_panels`。
- "检查一下 deck.md" → `validate`。
- "把 deck.md 做成 pptx" → 走 deck 格式文档 §5 的生态插件编排（此场景视为用户已确认渲染）。

局部任务不产生 jc.md、不占「当前项目」；输出位置用户可指定，默认就地。

## 4. 会话恢复

- **同会话**：上下文天然在。
- **新会话恢复**：用户在项目所在工作目录说"继续 journal club"，agent 读 jc.md 与产物文件实况（以文件实况为准修正 stage 缓存），报告"上次到图源核对，3 个 Figure 未核对"，从断点继续。
- **右侧栏轻发现**：JC tab 空态时扫描工作目录一级子文件夹中的 jc.md，列出项目名供点选——点击即向聊天预填恢复消息。**仅发现与打开，无任何管理功能**（不与「用户用文件夹管理」的原则冲突）；未发现时显示引导语："把论文 PDF 拖进聊天，或让我切分/拼图/渲染。"

## 5. jc.md —— 项目状态文件（新增契约）

项目文件夹根部新增 `jc.md`，人可读可改，agent 可解析：

```markdown
---
title: 联合治疗克服耐药
main_paper: main.pdf
supplement: supplement.pdf
stage: figure-review        # 缓存：analysis / figure-review / outline / deck / render / done
figures_revision: 3
requirements: "15 分钟，重点临床结果"
updated: 2026-10-26
---

# 项目备注
（agent 与用户自由记录；不影响流程）
```

- **stage 是缓存不是真相**：agent 与右侧栏状态卡每次以产物文件实况推断为准（analysis.md 存在且完整 = 步骤 1 完成），jc.md 的 stage 仅加速展示；发现不一致时 agent 顺手修正。
- 恢复入口、右侧栏状态卡、`requirements`（汇报要求）都以它为锚点。

## 6. skill 与工具的职责分层

| 层 | 职责 | 内容 |
|---|---|---|
| **工具层**（6 个原子工具） | 确定性能力，自描述 | parse_pdf / render_pages / detect_figures / crop / compose_panels / validate；不判断论文类型、不感知流程 |
| **skill 层**（journal-club skill） | 流程编排 + 领域知识 + 行为约定 | 四步剧本与三个确认点、叙事规则（发现覆盖/主线补充/疑点标记/科学表达）、边界判断（原创研究）、冲突先说明/大范围先讲计划的软约定、deck→PPTX 生态插件编排、恢复语义 |

局部任务只触达工具层；完整流程由 skill 编排工具层。

## 7. 示例对话

**发起（完整流程）**

> 用户：（拖入 paper.pdf）帮我准备这篇的 journal club，下周三组会，15 分钟
> agent：已创建项目 `联合治疗克服耐药/`（主论文已复制）。计划：论文分析 → 图源核对 → 大纲讲稿 → 幻灯片分页与 PPTX，每步关键点等你确认。汇报要求（15 分钟）已记录。开始论文分析……
> agent：（数分钟后）分析完成：38 页 · 7 Figure · 21 Panel · 3 个主要发现。底稿见 analysis.md，右栏可预览。图源候选已生成，请核对（右侧栏工作台或让我直接调整）。

**局部任务**

> 用户：把这个 PDF 的 figure 都切出来就行，不用做 PPT
> agent：好，只做切分。（执行 parse_pdf → detect_figures → crop）7 个 Figure、21 个 Panel 已裁出，在 `./figures/`。figures.json 附图注与页码。

**恢复**

> 用户：（新会话）继续上次的 journal club
> agent：找到项目 `联合治疗 overcome 耐药/`。当前进度：图源核对中——7 个 Figure 已核对 4 个，Figure 5 有 1 个疑点未处理。继续核对还是让我先处理疑点？
