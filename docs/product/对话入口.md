# 对话入口设计（v1）

> 隶属 [产品设计](产品设计.md) 的交互细化。覆盖：完整流程发起、局部任务直达、会话恢复、项目状态文件、skill 与工具的职责分层。

## 1. 入口总览

| 入口 | 用户行为 | agent 行为 | 副作用 |
|---|---|---|---|
| **完整流程** | 拖 PDF 进聊天（或给路径），表达汇报意图（"做 journal club / 准备组会汇报"） | 建项目文件夹、复制 PDF、写 jc.md、启动步骤 1 | 进入四步流程与确认点节奏 |
| **局部任务** | "把这个 PDF 的 figure 切出来 / 重新拼这张图 / 校验 slides.md / 渲染 pptx" | 直接组合原子工具执行，就地输出 | **不建项目文件夹、不进流程、不发流程卡片** |
| **恢复** | "继续 journal club"（新会话，工作目录下有项目） | 读 jc.md + 产物实况，从断点继续 | 无新增 |

意图模糊（拖了 PDF 没说话）时 agent 先问一句：完整汇报准备，还是只要切图/分析？——不猜。

## 2. 完整流程发起

### 2.1 触发

- skill 按请求自动匹配，触发词族：journal club / JC / 组会 / 文献汇报 / 论文汇报准备。
- PDF 来源：聊天附件拖入（dsh attachment）、工作目录内路径。主论文必备；补充材料可发起时一起给，或步骤 2 前说"补充材料是这个"再补（之后补入则 agent 重跑受影响的解析部分）。

### 2.2 首轮交互（不阻塞原则）

0. **前置检查（解析前一次性）**：随包 MinerU API runner 可运行且 API Key 已配置（高精度模式）。无需全局 CLI；配置 `MINERU_TOKEN`，或复用已有 `~/.mineru/config.yaml`。未配置时给出 mineru.net 注册与 Token 引导；用户选择试用时才使用 `--mode flash`（≤10MB/20 页、仅 Markdown、无结构化输出）。解析、下载和缓存由 runner 管理，重复命令恢复任务，具体参数见 [架构 §6.1](../architecture/架构设计.md#61-mineru-api-runner)。

1. agent 从 PDF 提取论文名，**直接确定**项目文件夹名并建立 `<论文名>/`、复制 PDF、写入 jc.md，并在 groups.json 不存在时初始化 `{ "version": 1, "groups": [] }`——不发起名确认（不满意随时说，agent 改名并迁移）。
2. 立即启动步骤 1（论文分析）；**同时异步问一次**："有汇报时长/重点要求吗？没有就按充分覆盖默认来，之后随时可改。"答案写入 jc.md 的 `requirements`，影响大纲与讲稿重点、详略和节奏，不阻塞步骤 1，也不授权为时长删减正文主图。
3. 首轮回复包含：项目路径、四步计划一句话、正在开始步骤 1。

### 2.3 边界拒绝（skill 层，不在工具层）

- 支持**原创研究**的完整流程；Review / Meta-analysis / 指南 / 病例报告 / 非生物医学 → agent 识别后说明完整流程不支持。
- **论文类型门槛只存在于 skill 编排**；原子工具不设论文类型判断——用户对一篇 Review 只要切图，照样可以（工具原子化的自然推论）。
- 扫描件 / 加密 / 损坏 PDF：确认文档本身不可解析时，如实提示提供可解析版本。上传、服务或结果下载失败分别报告实际错误并保留已有产物，不能据此要求更换 PDF 或静默切换解析引擎；Windows 命令的完成判定与已知下载超时限制见 [D41](../decisions.md#d41-mineru-下载超时与-powershell-退出码2026-11-04)。

## 3. 局部任务直达

工具自描述（描述即用法），agent 无需加载 JC skill 即可组合：

- "把这个 PDF 的图切出来" → 随包 runner 调用 MinerU API 解析（或用户明确选择的 agent 视觉定位）+ `render_pages` + agent 视觉切 panel（经 `update_figures` 产 figures.json）+ `crop`，就地输出。
- "这四张 panel 拼成一页" → `compose_panels`（组合图 + groups.json）；用户也可从 JC tab 的「自由拼图」入口手动调整，支持任意画布比例与图片数量。
- "检查一下 slides.md" → `validate`。
- "把 slides.md 做成 pptx" → 走 slides 格式文档 §5 的生态插件编排（此场景视为用户已确认渲染）。

局部任务不产生 jc.md、不占「当前项目」；输出位置用户可指定，默认就地。

## 4. 会话恢复

- **同会话**：上下文天然在。
- **新会话恢复**：用户在项目所在工作目录说"继续 journal club"，agent 读 jc.md 与产物文件实况（以文件实况为准修正 stage 缓存），报告"上次到图源核对，3 个 Figure 未核对"，从断点继续。**确认有效性按 digest 比对**：jc.md 的 confirmations 记录与当前 outline.md/slides.md/groups.json 内容摘要一致 = 该版本已确认；不一致或无记录 = 内容已变或未确认，**停在该确认点等用户**，不自行推进。
- **右侧栏入口**：按会话恢复上次项目与页面；没有记忆时扫描 cwd 与一级子目录的 jc.md / figures.json / groups.json，多个候选才显示目录选择。显式卡片入口优先，例如「打开核对工作台」直接进图源页。完整项目在独立概览提供「在对话中继续」；局部任务只显示相应文件和工具页面。只发现与打开，无项目管理功能，详见 [产品设计 §3.1](产品设计.md#31-工作台导航与局部使用)。

完整流程到达确认点时，skill 在回复中输出 `<!-- jc-card {"project":"论文项目相对路径","stage":"figures"} -->`；stage 可为 figures / outline / slides。宿主将标记解析成聊天卡片，按钮打开当前文件或工作台，确认按钮通过 `sessions.scope(sessionId)` 获取当前会话作用域，再用该作用域的 `get('conversation')` 获取服务并 `send(text)`，发送带项目路径的标准确认文本。会话或服务不可用时显示错误，不回退到其他会话。卡片本身不写确认记录，不证明当前文件已确认；agent 收到明确操作后核对版本并记录。局部任务不发流程卡片。

## 5. jc.md —— 项目状态文件（新增契约）

项目文件夹根部新增 `jc.md`，人可读可改，agent 可解析：

```markdown
---
title: 联合治疗克服耐药
main_paper: main.pdf
supplement: supplement.pdf
stage: figure-review        # 缓存：analysis / figure-review / outline / slides / render / done
requirements: "15 分钟，重点临床结果"
confirmations:
  figures: { revision: 3, at: 2026-10-26T14:00 }
  # outline: { digest: sha256:…, at: … }
  # slides:    { digest: sha256:…, groups_digest: sha256:…, at: … }
updated: 2026-10-26
---

# 项目备注
（agent 与用户自由记录；不影响流程）
```

- **stage 是缓存不是真相**：agent 与右侧栏概览每次以产物文件实况推断为准（analysis.md 存在且完整 = 步骤 1 完成），jc.md 的 stage 仅加速展示；发现不一致时 agent 顺手修正。
- **confirmations 是确认的持久化**：文件存在不等于已确认——「已生成待确认」与「已确认」由本段区分；确认后文件被编辑（digest 变化）或图组重拼（groups_digest 变化）即视为确认失效，恢复时停在该确认点。digest 取落盘原始字节的 SHA-256，不进行换行、BOM 或空白归一化；优先使用 helper 的 `digestFile`。
- 完整汇报的恢复入口与 `requirements`（汇报要求）以它为锚点；图源与拼图工具不依赖 jc.md，概览以各自产物为事实。
- 随包 helper `dsh-journal-club/project` 提供文件读写、摘要与确认核对；内联记录支持未加引号的 ISO 时间和 sha256 摘要。完整文件示例随 skill 的 `references/formats.md` 交付，注册内容提供安装目录与 helper 路径。

## 6. skill 与工具的职责分层

| 层 | 职责 | 内容 |
|---|---|---|
| **工具层**（5 个原子工具） | 确定性能力，自描述 | render_pages / crop / compose_panels / update_figures / validate；不判断论文类型、不感知流程 |
| **skill 层**（journal-club skill） | 流程编排 + 领域知识 + 行为约定 | 四步剧本与三个确认点、叙事规则（发现覆盖/主线补充/疑点标记/科学表达）、边界判断（原创研究）、冲突先说明/大范围先讲计划的软约定、slides→PPTX 生态插件编排、恢复语义 |

局部任务只触达工具层；完整流程由 skill 编排工具层。

## 7. 示例对话

**发起（完整流程）**

> 用户：（拖入 paper.pdf）帮我准备这篇的 journal club，下周三组会，15 分钟
> agent：已创建项目 `联合治疗克服耐药/`（主论文已复制）。计划：论文分析 → 图源核对 → 大纲讲稿 → 幻灯片分页与 PPTX，每步关键点等你确认。汇报要求（15 分钟）已记录。开始论文分析……
> agent：（数分钟后）分析完成：38 页 · 7 Figure · 21 Panel · 3 个主要发现。底稿见 analysis.md，右栏可预览。图源候选已生成，请核对（右侧栏工作台或让我直接调整）。

**局部任务**

> 用户：把这个 PDF 的 figure 都切出来就行，不用做 PPT
> agent：好，只做切分。（执行 MinerU 解析 → render_pages → 视觉切 panel → crop）7 个 Figure、21 个 Panel 已裁出，在 `./figures/`。figures.json 附图注与页码。

**恢复**

> 用户：（新会话）继续上次的 journal club
> agent：找到项目 `联合治疗 overcome 耐药/`。当前进度：图源核对中——7 个 Figure 已核对 4 个，Figure 5 有 1 个疑点未处理。继续核对还是让我先处理疑点？
