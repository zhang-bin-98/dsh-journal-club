# dsh-journal-club 产品设计（v0.2）

> 状态：待用户确认。本文件是产品层面的唯一权威；架构与数据契约后续另立文档。
> 参考项目：`E:\project\SmartJC`（独立 PWA 形态的同类产品，叙事规则与流程设计的主要来源）。
> 目标平台：[DeepSeek Harness (dsh)](https://github.com/deepseek-ai/deepseek-harness) 插件。

## 1. 产品定位

dsh-journal-club 是运行在 DeepSeek Harness（dsh）内的生物医学论文 Journal Club 汇报工具：研究者在会话工作目录中发起，由 agent 完成论文解析、图源切分、叙事大纲与幻灯片分页（deck.md，含拼合图组），交付一份内容完整、图文对照、可直接转 PPTX 的 markdown 版幻灯片。

- 移植自 SmartJC 的产品闭环与科研叙事规则，运行形态从「浏览器 PWA + 用户自带 Key」换成「dsh 插件 + harness 托管的 agent/LLM/文件系统」。
- 主要用户：准备 Journal Club、组会和文献汇报的生物医学研究人员。
- 成功标准沿用 SmartJC：论文发现覆盖充分、图证据完整可读、讲稿与页面相互配合、来源可查；用户主要做取舍和修改。
- 设计原则一：**文件即真相**。所有中间产物是工作目录里的普通文件（markdown + 图片 + JSON），用户可用任意工具查看与编辑，dsh 右侧栏预览自动刷新；插件不发明私有存储。
- 设计原则二：**agent 信任与自由度**。不自建预览确认门、审批流等第二套监督机制——agent 修改产物文件与它编辑代码文件同等地位，diff 在聊天流天然可见。skill 以提示词约定行为礼貌（与人工调整冲突先说明、大范围操作先讲计划），不设硬门。
- 设计原则三：**工具原子化，组合优于流程**。每个工具独立可用、以文件为输入输出接口，工具之间零耦合；四步流程只是 skill 编排的默认剧本，不是工具层约束。局部使用是合法场景：用户只要 figure 切分、只要拼图、只要校验，agent 直接组合对应工具交付，不强制进入完整 JC 流程。

## 2. 核心闭环

**在会话工作目录发起 → 插件建项目子文件夹并复制 PDF → 论文解析与自动切图 → 图源核对【确认点 1】→ 叙事大纲 outline.md【确认点 2】→ 幻灯片分页 deck.md 与拼图【确认点 3：渲染前确认内容与拼图效果】→ PPTX 渲染（agent + 生态插件）。**

- 四步沿用 SmartJC 节奏：论文分析、图源核对、大纲与讲稿、幻灯片分页。
- 人工介入为「关键点确认」，三个暂停点：图源核对完成、outline.md 完成、deck.md 完成后**渲染 PPTX 之前**。确认点 3 的逻辑是成本门槛——markdown 预览与拼图重跑是秒级，PPTX 渲染是分钟级，先在轻量层确认内容与拼图效果再渲染。各确认点之间与确认之后的编辑始终自由（改 → 预览自动刷新），确认是流程推进开关，不是编辑锁。
- 每步产物落盘；用户可随时通过对话发起局部修改，agent 编辑文件（diff 在聊天可见），预览自动跟随。

## 3. 产品形态（dsh 内的载体）

以一个 dsh 插件（bundle）交付，包含技能（skill）、工具（tools）与 UI 扩展三部分：

| 载体 | 职责 |
|---|---|
| 聊天富卡片 | 流程推进的主线：各步骤状态卡片与确认按钮（如图源卡片的进度摘要 +「打开核对工作台」+「确认图源」快捷入口）；**不承载长时间精细交互**，输入经 `agent.followup()` 回流 |
| 侧边工作台面板 | 注册 dsh 右侧栏一个「Journal Club」tab：**当前项目**状态卡（项目文件夹路径、四步进度、每步产物的预览入口）；图源核对步骤时切入**核对工作台**（Figure 连续列表、框叠加、调框等全部框操作，从 figures.json 实时驱动，agent 修改后自动刷新并高亮变更）。**无项目列表**——项目即文件夹，由用户在资源管理器中自行管理；未在处理项目时显示空态引导 |
| dsh 文档预览（依赖，不自研） | outline.md、deck.md（markdown，支持内嵌图片相对路径引用）、图源图片（PNG/JPG 直开）统一走 dsh 右侧栏 `ui-sidebar-documentpreview`，插件经 `ctx.sidebarRight.openResource()` 唤起；预览随文件变化自动刷新 |
| 工具与技能 | 原子工具注册进 `ctx.tools`（见 5.1，共 5 个：渲染、裁切、拼图、图源写入、校验）；PDF 解析编排官方 `mineru-open-api` CLI；Panel 切分由 agent 视觉完成；四步流程编排与叙事规则维护在 skill 中 |
| 数据落盘 | 项目文件夹 = 会话工作目录下以论文命名的子文件夹 `<会话工作目录>/<论文名>/`；PDF 复制入内，全部产物（jc.md 状态文件、解析 JSON、图源资产与 figures.json、analysis.md、outline.md、deck.md）都在其中；同一工作目录多次 JC 各占独立子文件夹 |

## 4. 分步设计

### 4.1 项目准备
- 入口设计与触发语义见 [对话入口](对话入口.md)：完整流程（建项目）与局部任务（工具直连、无项目副作用）分流；新会话可恢复。
- 用户在当前会话工作目录发起：拖入论文 PDF 或给出路径，可附一份补充材料 PDF。
- 插件建立 `<论文名>/` 子文件夹，将 PDF 复制入内，写入项目状态文件 `jc.md`（frontmatter：论文名、文件、stage 缓存、汇报要求），后续产物全部写在该文件夹中。
- 不做项目列表、重命名、删除等管理 UI；用户用文件夹操作管理一切。
- 「当前项目」跟随本会话最近处理的论文文件夹。

### 4.2 论文分析
- agent 解析 PDF：正文、方法、图注、表格；自动切分全部 Figure/Panel 并裁切落盘。
- 生成论文底稿 analysis.md：研究问题、方法、发现（主线/补充标注）、发现—证据（Panel）关联；发现与观察用引用块 + 页码锚定原文，保证可溯源。
- 卡片展示分析进度与底稿摘要；分析完整单元及时保存，失败不破坏已保存部分。

### 4.3 图源核对（确认点 1）

交互细化见 [图源核对](图源核对.md)。要点：**右侧栏 JC 工作台为核对主工作区**（Figure 连续列表、框叠加、四角手柄调框、增删 Panel、改标签、裁切预览、图注高亮、疑点标注、放大编辑），从 figures.json 实时驱动；聊天卡片为轻量入口（进度摘要 + 打开工作台 + 快捷确认）。连续浏览 + 一次整体确认（不逐图勾选，有未查看/疑点时提示不阻断）；对话修正与工作台编辑统一经 `update_figures` 写入（乐观锁防并发覆盖，diff 聊天可见、工作台自动刷新并高亮变更框）；确认时定稿并从 PDF 重裁落盘、写入确认记录。

### 4.4 叙事大纲 outline.md（确认点 2）
- 基于论文底稿生成 outline.md：讲述结构（背景 → 方法 → 发现 → 局限与启发）、发现覆盖与主线/补充标注、证据（Panel）关联。
- **维护即编辑 markdown 文件**：预览走 dsh 右侧栏（自动刷新）；修改两途径——对话让 agent 改（diff 在聊天可见），或用户用任意编辑器直接改。
- agent 在 outline.md 确认后进入分页。

### 4.5 幻灯片分页 deck.md（确认点 3：渲染前确认）
- 按大纲分页生成 deck.md，格式契约见 [deck 格式](deck格式.md)：frontmatter + `---` 分页 + 页头注释（页号/布局建议）+ 正文（标题/要点/图像引用/来源标注）+ 讲稿引用块（可见，图文对照）。
- 自研「拼图模块」负责 Panel 图组的有限矩形分区布局（对应 SmartJC 的图组分区与候选评分，规模缩小为一个小模块），产物为组合 PNG + 几何信息，被 deck.md 引用；**组合图登记 groups.json**（成员 Panel、输入指纹、布局几何——证据校验与重建判定的机器可读契约）；组合图文件名稳定，重拼后 deck.md 引用不变，预览自动刷新；成员被重裁时提示重建。
- **确认点 3**：deck.md 生成后 agent 停止，聊天卡片提供「打开 deck.md 预览」+「确认渲染 PPTX」。用户在秒级 markdown 预览中确认每页内容、讲稿与**拼图效果**（组合 PNG 内嵌可见）；拼图不满意 → 对话指令重拼（`compose_panels` 秒级重跑）；内容不满意 → 对话或直接编辑 deck.md。确认后才进入分钟级 PPTX 渲染。确认后仍可改 deck.md 再次渲染，不锁死。
- **内容级预览** = deck.md 的 markdown 预览；**视觉级 PPTX** 由 agent 读 deck.md 调用生态插件（推荐 dsh-ppt-maker：PPTD 工程 + 质检 + 导出 + 可视化工作台微调）完成。渲染后纯视觉微调可直接在 dsh-ppt-maker 工作台进行，不回写 deck.md（单向派生）。
- 交付前 `validate` 工具校验 deck.md：页号连续、图像引用存在、页内容分配无冲突、每页讲稿完整（详见 4.6 一致性校验）。

### 4.6 证据关联与图文对应（贯穿 4.2–4.5 的横向机制）

移植 SmartJC 证据网络的内核，交互让位给文件与对话：

- **内嵌图即关联**：outline.md 讲述段落与 deck.md 页面通过 markdown 图片引用关联 Panel（文件名 = 稳定 ID），图片下方一行来源标注（图号 · 页码 · 图注摘录）。多对多天然成立：一段嵌多图、一图被多段嵌；主论文与补充 PDF 的图都可参与任何讲述，汇报顺序独立于论文图号。
- **正文可溯源**：analysis.md 发现/观察引用块 + 页码锚定原文；完整图注存 figures.json，outline/deck 按需摘录。
- **疑点标记**：skill 要求 LLM 对证据不充分的解释在 md 中显式标注疑点（`⚠️`），不得静默编造或升级因果——SmartJC 科学表达规则的延续。
- **一致性校验（交付前，分层）**——程序（validate）只管可判定项：引用了不存在的图或图组成员无效 → 错误必须修复；每页讲稿块缺失 → 错误（讲者备注是交付承诺，阻断渲染）；未被任何讲述引用的 Panel → 覆盖提醒（不阻断，尊重用户主动弃图）；deck 页放图但讲稿未讲 / 讲稿讲图但页未放 → 提醒；图组成员被重裁（指纹不匹配）→ 提醒重建。**发现覆盖归 agent 语义自查**（skill 剧本：outline/deck 确认前对照 analysis.md 发现清单，缺口写入回复）——自由文本无发现 ID，程序不承诺语义判定。
- **反向查询走对话**：「Figure 4B 用在哪些段落？」agent 扫描文件即答，不自研双向跳转 UI。

## 5. 第一版边界

### 5.1 自研清单（v1 全部开发量）

| 类别 | 内容 |
|---|---|
| 富交互 UI | 右侧栏图源核对工作台（Figure 列表、框叠加、四角手柄调框、增删 Panel、改标签、裁切预览、图注高亮、放大编辑） |
| 薄 UI | 聊天流程卡片（状态摘要、确认按钮、打开工作台/预览入口）+ 右侧栏状态卡与轻发现 |
| 原子工具 | 各自独立可用、以文件为接口、零相互耦合：**render_pages**（页面渲染 → 底图 PNG）、**crop**（按框裁切 → Panel PNG）、**compose_panels**（图组分区布局 → 组合 PNG + groups.json 登记）、**update_figures**（figures.json 唯一写入通道：json-patch + base-rev 乐观锁 + 原子替换 + 滚动快照，UI 与 agent 共用，防并发覆盖）、**validate**（deck/outline/figures/groups 一致性校验 → 报告）。PDF 解析不自研（官方 mineru-open-api CLI）；Panel 切分不自研算法（agent 视觉 + crop 反馈迭代） |
| 内容资产 | skill：四步流程编排 + 科研叙事提示词（发现覆盖、主线/补充、证据关联规则）+ agent 行为约定（冲突先说明、大范围操作先讲计划） |

analysis.md / outline.md / deck.md 的生成本身不写代码，由 agent 执行 skill 产出。工具间衔接全部通过中间产物文件完成，任何工具可被单独调用（如只切图、只拼图、只校验）。

### 5.2 包含

单篇论文四步闭环、自动切图 + 简化调框核对、三个确认点（图源 / outline / deck 渲染前）、outline.md / deck.md 文件化产物与对话式修改、拼图模块、证据关联（内嵌图即关联、疑点标记、覆盖不阻断）、一致性校验。

### 5.3 明确不自研（依赖 dsh / 生态现成能力）

- PDF 文档解析（文本、阅读顺序、表格、图注、整图定位、LaTeX 公式）——官方 `mineru-open-api` CLI（OpenDataLab 维护；云端服务，论文 PDF 需上传，配置说明中明示）。**完整流程需高精度模式**：注册 MinerU 账号（mineru.net）→ 控制台获取 API Key → 一次性配置（`mineru-open-api auth` 或 `MINERU_TOKEN`）；skill 在首次解析前检测并给出注册引导。未注册仅可用免费快速模式（≤10MB/20 页、仅 Markdown、无结构化输出，整图定位退化为 agent 视觉，质量降级，定位为试用）。
- Panel 切分算法与 OCR——agent 多模态视觉（harness 托管）+ crop 反馈迭代，本地不建几何/OCR 引擎。
- markdown 与图片预览——统一走 dsh 右侧栏文档预览（`ui-sidebar-documentpreview`），我们只做「打开预览」入口。
- LLM 调用、会话管理、文件系统、权限审批——由 dsh harness 托管。
- PPTX 生成与视觉级预览——交给 dsh 生态插件（推荐 dsh-ppt-maker），我们只保证 deck.md 契约清晰。

### 5.4 不包含（沿用 SmartJC 的排除项并叠加本次取舍）
- 项目列表/项目管理 UI（文件夹即项目）。
- 像素级切分工作台（跨页图块、Undo/Redo）、幻灯片自由编辑器、富文本编辑。
- PPTX 生成器与 PPTX 视觉预览（v1；生态插件路径写入使用说明）。
- 账号、云同步、多人协作、多论文工作区、模板市场、联网补充材料、PPTX 导入。
- 非Story类论文（Review、Meta-analysis、指南、病例报告）与非生物医学领域。

## 6. 与 SmartJC 的功能对应

| SmartJC | dsh-journal-club | 变化 |
|---|---|---|
| PWA 项目列表 + IndexedDB | 文件夹即项目，无管理 UI | 存储换文件系统，管理归用户 |
| 浏览器 PDF.js 解析 | harness 侧解析工具 | 能力增强 |
| 图源切分工作台 | 右侧栏核对工作台（框叠加 + 简化调框）+ 聊天轻卡片（摘要与快捷确认） | 降交互复杂度 |
| 大纲/讲稿编辑页 | outline.md / deck.md 文件 + 对话修改；预览走 dsh markdown 预览（自动刷新） | 载体变化，不自研编辑器与渲染 |
| 幻灯片编辑器 + PPTX 导出 | deck.md + 拼图模块；PPTX 生成交生态插件 | 交付形态变为 md 契约 |
| 用户自带 Key / Responses API | dsh 托管 LLM（`ctx.llm`） | 配置归 harness |
| pi-agent-core 问答 agent | dsh agent 会话 | 平台原生 |
