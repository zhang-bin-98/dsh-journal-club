# dsh-journal-club 产品设计（v0.2）

> 状态：已确认的产品契约；实现与验收状态见 [架构设计 §7](../architecture/架构设计.md)。本文件不以设计描述代替验收证据。
> 参考项目：SmartJC（独立 PWA 形态的同类产品，复用来源见 [架构 §1.3](../architecture/架构设计.md#13-smartjc-资产复用清单复用优先按搬运方式分级)）。
> 目标平台：[DeepSeek Harness (dsh)](https://github.com/deepseek-ai/deepseek-harness) 插件。

## 1. 产品定位

dsh-journal-club 是运行在 DeepSeek Harness（dsh）内的生物医学论文 Journal Club 汇报工具：研究者在会话工作目录中发起，由 agent 完成论文解析、图源切分、叙事大纲与幻灯片分页（slides.md，含拼合图组），交付一份内容完整、图文对照、可直接转 PPTX 的 markdown 版幻灯片。

- 移植自 SmartJC 的产品闭环与科研叙事规则，运行形态从「浏览器 PWA + 用户自带 Key」换成「dsh 插件 + harness 托管的 agent/LLM/文件系统」。
- 主要用户：准备 Journal Club、组会和文献汇报的生物医学研究人员。
- 成功标准沿用 SmartJC：论文发现覆盖充分、图证据完整可读、讲稿与页面相互配合、来源可查；用户主要做取舍和修改。
- 设计原则一：**文件即真相**。所有中间产物是工作目录里的普通文件（markdown + 图片 + JSON），用户可用任意工具查看与编辑，dsh 右侧栏预览自动刷新；插件不发明私有存储。
- 设计原则二：**agent 信任与自由度**。不自建预览确认门、审批流等第二套监督机制——agent 修改产物文件与它编辑代码文件同等地位，diff 在聊天流天然可见。skill 以提示词约定行为礼貌（与人工调整冲突先说明、大范围操作先讲计划），不设硬门。
- 设计原则三：**工具原子化，组合优于流程**。每个工具独立可用、以文件为输入输出接口，工具之间零耦合；四步流程只是 skill 编排的默认剧本，不是工具层约束。局部使用是合法场景：用户只要 figure 切分、只要拼图、只要校验，agent 直接组合对应工具交付，不强制进入完整 JC 流程。

## 2. 核心闭环

**在会话工作目录发起 → 插件建项目子文件夹并复制 PDF → 论文解析与自动切图 → 图源核对【确认点 1】→ 叙事大纲 outline.md【确认点 2】→ 幻灯片分页 slides.md 与拼图【确认点 3：渲染前确认内容与拼图效果】→ PPTX 渲染（agent + 生态插件）。**

- 四步沿用 SmartJC 节奏：论文分析、图源核对、大纲与讲稿、幻灯片分页。
- 人工介入为「关键点确认」，三个暂停点：图源核对完成、outline.md 完成、slides.md 完成后**渲染 PPTX 之前**。确认点 3 的逻辑是成本门槛——markdown 预览与拼图重跑是秒级，PPTX 渲染是分钟级，先在轻量层确认内容与拼图效果再渲染。各确认点之间与确认之后的编辑始终自由（改 → 预览自动刷新），确认是流程推进开关，不是编辑锁。
- 默认每个确认点都展示当前产物与对应卡片，**结束本轮回复并等待用户**；首次完整流程先停在图源核对，确认后生成大纲，大纲确认后生成文稿，三项确认有效后才进入 PPTD/PPTX。不能先生成后续产物再以「尚未确认的草稿」代替暂停。首次「做中文 PPT，15 分钟」表达完整汇报需求；宿主免工具审批、解析失败后的「继续」均不构成内容确认。用户明确要求跳过指定确认点或直接渲染已有/当前文稿时按其范围执行，如实保留缺失记录，不补造确认。
- 每步产物落盘；用户可随时通过对话发起局部修改，agent 编辑文件（diff 在聊天可见），预览自动跟随。

## 3. 产品形态（dsh 内的载体）

以一个 dsh 插件（bundle）交付，包含技能（skill）、工具（tools）与 UI 扩展三部分：

| 载体 | 职责 |
|---|---|
| 聊天富卡片 | 流程推进的主线：各步骤状态卡片与确认按钮（如图源卡片的进度摘要 +「打开核对工作台」+「确认图源」快捷入口）；**不承载长时间精细交互**，输入经宿主会话作用域的 `get('conversation').send(text)` 回流 |
| 侧边工作台面板 | 注册 dsh 右侧栏「Journal Club」tab，顶部为项目名与切换入口，下方「概览 / 图源核对 / 自由拼图」页面导航。概览独立显示产物与确认有效性，不再用抽屉挤占编辑区；按会话恢复上次项目与页面。项目即文件夹，选择页只发现与打开，不提供项目管理。局部工具按已有文件呈现可用页面 |
| dsh 文档预览（依赖，不自研） | outline.md、slides.md（markdown，支持内嵌图片相对路径引用）、图源图片（PNG/JPG 直开）统一走 dsh 右侧栏 `ui-sidebar-documentpreview`，插件经 `ctx.sidebarRight.openResource()` 唤起；预览随文件变化自动刷新 |
| 工具与技能 | 原子工具注册进 `ctx.tools`（见 5.1，共 5 个：渲染、裁切、拼图、图源写入、校验）；PDF 解析由随包 Node 脚本调用官方 MinerU API；Panel 切分由 agent 视觉完成；四步流程编排与叙事规则维护在 skill 中 |
| 数据落盘 | 项目文件夹 = 会话工作目录下以论文命名的子文件夹 `<会话工作目录>/<论文名>/`；PDF 复制入内，全部产物（jc.md 状态文件、解析 JSON、图源资产与 figures.json、analysis.md、outline.md、slides.md）都在其中；同一工作目录多次 JC 各占独立子文件夹 |

### 3.1 工作台导航与局部使用

- 显式入口指定的项目和页面优先；普通打开按会话恢复上次项目、页面以及项目内选中的 Figure/Panel/拼图。无记忆时才按现有文件与 stage 提示选择初始页；背景文件更新只刷新内容，不跳页。根目录本身也可以是项目。
- 首次有多个候选或主动「切换项目」时显示简洁目录列表，展示已有图源、拼图、大纲与文稿；只扫描 cwd 和一级子目录中的 `jc.md`、`figures.json`、`groups.json`。重新扫描只在选择页提供，不做全局刷新。
- 完整项目概览读取 `jc.md` 确认记录与当前 revision/digest，对图源、大纲、文稿分别显示待产出、待确认、已确认或来源已变更；analysis 只显示产物实况，不虚构完成百分比。PPTX 存在不代表与当前内容同步。概览以一张「当前状态 + 下一步」主卡作为视觉中心：读取失败或确认异常优先，其次确认失效与待产出/待确认事项，确认有效且有 PPTX 时仅提示打开检查。下方常显紧凑阶段摘要，再列最多三项主要产物；阶段原因与全部文件收进可展开详情，窄栏产物改为单列。
- 无 `jc.md` 的切图项目直接进入图源核对；已有 `groups.json` 的局部拼图直接进入拼图。概览只展示局部文件与数量，不提示补齐完整汇报流程。只有图源时可新建第一张拼图；只有拼图时按清单成员恢复已存在的 `figures/<id>.png`，不自动创建图源契约，也不扫描散图。
- 页面切换保持编辑器与草稿；写入进行中不能切项目/关闭，未保存调整在离开时提示。宿主关闭回调保护显式关闭，插件卸载或应用退出仍会结束组件生命周期；草稿不作为持久化状态。
- 与宿主共享 `--dsw-*` 主题及字体，字体与中性色跟随宿主；交互蓝使用宿主链接色（回退 #2563EB），主按钮用深蓝白字，不绑定宿主近黑品牌/按钮变量。使用紧凑工具栏、浅灰分隔、蓝色焦点和原生表单控件。PDF 与拼图编辑区使用冷灰衬底，图像本身不改色。窄区素材移到画布下方，放大仍复用原编辑器。局部核对不出现生成大纲按钮。

## 4. 分步设计

### 4.1 项目准备
- 入口设计与触发语义见 [对话入口](对话入口.md)：完整流程（建项目）与局部任务（工具直连、无项目副作用）分流；新会话可恢复。
- 用户在当前会话工作目录发起：拖入论文 PDF 或给出路径，可附一份补充材料 PDF。
- 插件建立 `<论文名>/` 子文件夹，将 PDF 复制入内，写入项目状态文件 `jc.md`（frontmatter：论文名、文件、stage 缓存、汇报要求），后续产物全部写在该文件夹中。尚未识别论文名时，先用 PDF 文件名作临时目录名，复制主文后通过 `render_pages` 首页图识别标题与论文类型，再改为正式目录名；首页图随项目保留，不写到外部附件目录。默认不探测或安装 Python PDF 引擎；完整启动顺序见 [对话入口 §2.2](对话入口.md#22-首轮交互不阻塞原则)。
- 不做项目列表、重命名、删除等管理 UI；用户用文件夹操作管理一切。
- 「当前项目」跟随本会话最近处理的论文文件夹。

### 4.2 论文分析
- agent 解析 PDF：正文、方法、图注、表格；自动切分全部 Figure/Panel 并裁切落盘。
- 生成论文底稿 analysis.md：研究问题、方法、发现（主线/补充标注）、发现—证据（Panel）关联；发现与观察用引用块 + 页码锚定原文，保证可溯源。
- 卡片展示分析进度与底稿摘要；分析完整单元及时保存，失败不破坏已保存部分。

### 4.3 图源核对（确认点 1）

交互细化见 [图源核对](图源核对.md)。要点：**右侧栏 JC 工作台为核对主工作区**（Figure 连续列表、框叠加、四角手柄调框、增删 Panel、改标签、裁切预览、图注高亮、疑点标注、放大编辑），从 figures.json 实时驱动；聊天卡片为轻量入口（进度摘要 + 打开工作台 + 快捷确认）。连续浏览（可折叠、按未查看/疑点筛选，确认入口保留在聊天卡片与概览）+ 一次整体确认（不逐图勾选，有未查看/疑点时提示不阻断）；对话修正与工作台编辑统一经 `update_figures` 写入（乐观锁防并发覆盖，diff 聊天可见、工作台自动刷新并高亮变更框）；确认时定稿并从 PDF 重裁落盘、写入确认记录。

### 4.4 叙事大纲 outline.md（确认点 2）
- 基于论文底稿生成 outline.md：讲述结构（论文身份 → 背景与知识缺口 → 研究问题与总体设计 → 按科学问题串联的结果及就近方法 → 综合解释、局限 → 结论与讨论）、发现覆盖与主线/备份标注、证据（Panel）关联。结构按研究类型适配，不强制固定页数或每项单独一页。
- **维护即编辑 markdown 文件**：预览走 dsh 右侧栏（自动刷新）；修改两途径——对话让 agent 改（diff 在聊天可见），或用户用任意编辑器直接改。
- 正文主图及其所有标号 Panel 默认在正式汇报正文清晰展示，可整图或拆页/拼图累计覆盖，不能只放部分 Panel、不可读缩略图或备份页抵充。主图/补图按论文编号与图注区分，不按 PDF 文件角色区分；用户明确取舍的例外保留，缺图如实说明。
- 时长通过讲稿详略与节奏调节：压缩铺垫与重复说明，保留正文主图、关键对照和阴性结果。按图密度等估计主线时长区间，备份与问答另计；仍超时则在既有确认点披露差距，不自行删图或虚报耗时。大纲末尾记录图到证据单元的计划覆盖/节奏表，不固定页码、不增加状态字段。
- agent 在 outline.md 确认后进入分页。

### 4.5 幻灯片分页 slides.md（确认点 3：渲染前确认）
- 按大纲分页生成 slides.md，格式契约见 [slides 格式](slides格式.md)：frontmatter + `---` 分页 + 页头注释（页号/布局建议）+ 正文（标题/要点/图像引用/来源标注）+ 讲稿引用块（可见，图文对照）。
- 「自由拼图」页面允许手动拖动、等比缩放 Panel，编辑区随图片位置扩展，保存按图片实际外缘导出，不设固定比例与图片数量上限；系统建议排版作为可撤销的起点（交互见 [自由拼图](自由拼图.md)），产物为组合 PNG + 几何信息，被 slides.md 引用；**组合图登记 groups.json**（成员 Panel、输入指纹、布局几何——证据校验与重建判定的机器可读契约）；组合图文件名稳定，重拼后 slides.md 引用不变，预览自动刷新；成员被重裁时提示重建。
- **确认点 3**：slides.md 生成后 agent 停止，聊天卡片提供「打开 slides.md 预览」+「确认渲染 PPTX」。大纲与分页确认卡仅聚焦对应文档和确认按钮，不重复加载图源缩略图。用户在秒级 markdown 预览中确认每页内容、讲稿与**拼图效果**（组合 PNG 内嵌可见）；拼图不满意 → 打开「自由拼图」手调并保存，或对话指令重拼（`compose_panels` 共用同一导出核心）；内容不满意 → 对话或直接编辑 slides.md。确认后才进入分钟级 PPTX 渲染。确认后仍可改 slides.md 再次渲染，不锁死。
- **内容级预览** = slides.md 的 markdown 预览；**视觉级 PPTX** 由 agent 读 slides.md 调用生态插件（推荐 dsh-ppt-maker：PPTD 工程 + 质检 + 导出 + 可视化工作台微调）完成。渲染后纯视觉微调可直接在 dsh-ppt-maker 工作台进行，不回写 slides.md（单向派生）。
- 交付前 `validate` 工具校验 slides.md：页号连续、图像引用存在、页内容分配无冲突、每页讲稿完整（详见 4.6 一致性校验）。

### 4.6 证据关联与图文对应（贯穿 4.2–4.5 的横向机制）

移植 SmartJC 证据网络的内核，交互让位给文件与对话：

- **内嵌图即关联**：outline.md 讲述段落与 slides.md 页面通过 markdown 图片引用关联 Panel（文件名 = 稳定 ID），图片下方一行来源标注（图号 · 页码 · 图注摘录）。多对多天然成立：一段嵌多图、一图被多段嵌；主论文与补充 PDF 的图都可参与任何讲述，汇报顺序独立于论文图号。
- **正文可溯源**：analysis.md 发现/观察引用块 + 页码锚定原文；完整图注存 figures.json，outline/slides 按需摘录。
- **疑点标记**：skill 要求 LLM 对证据不充分的解释在 md 中显式标注疑点（`⚠️`），不得静默编造或升级因果——SmartJC 科学表达规则的延续。认定原文矛盾前须回查原页，排除识读错误；模型模拟、条件子群结果和批评性判断均保留证据范围，具体规则见随包 narrative.md。
- **一致性校验（交付前，分层）**——程序（validate）只管可判定项：引用了不存在的图或图组成员无效 → 错误必须修复；每页讲稿块缺失 → 错误（讲者备注是交付承诺，阻断渲染）；未被任何讲述引用的 Panel → 覆盖提醒（不阻断局部工具或用户明确取舍；完整汇报由 agent 区分主图缺口与补图取舍）；slides 页放图但讲稿未讲 / 讲稿讲图但页未放 → 提醒；图组成员被重裁（指纹不匹配）→ 提醒重建。**发现覆盖归 agent 语义自查**（skill 剧本：outline/slides 确认前对照 analysis.md 发现清单与原文主图/标号 Panel；slides 确认回复列实际正文页映射与例外，缺口写入回复，不为填最终页码回写已确认大纲）——自由文本无发现 ID，程序不承诺语义判定。
- **反向查询走对话**：「Figure 4B 用在哪些段落？」agent 扫描文件即答，不自研双向跳转 UI。

## 5. 第一版边界

### 5.1 自研清单（v1 全部开发量）

| 类别 | 内容 |
|---|---|
| 富交互 UI | 右侧栏图源核对工作台（Figure 列表、框叠加、四角手柄调框、增删 Panel、改标签、裁切预览、图注高亮、放大编辑） |
| 薄 UI | 聊天流程卡片（状态摘要、确认按钮、打开工作台/预览入口）+ 独立概览与目录选择 |
| 原子工具 | 各自独立可用、以文件为接口、零相互耦合：**render_pages**（页面渲染 → 底图 PNG）、**crop**（按框裁切 → Panel PNG）、**compose_panels**（建议排版或自由几何 → 组合 PNG + groups.json 登记）、**update_figures**（figures.json 唯一写入通道：json-patch + base-rev 乐观锁 + 原子替换 + 滚动快照，UI 与 agent 共用，防并发覆盖）、**validate**（slides/outline/figures/groups 一致性校验 → 报告）。PDF 解析算法不自研（官方 MinerU API，随包 Node 脚本仅处理传输、恢复与文件校验）；Panel 切分不自研算法（agent 视觉 + crop 反馈迭代） |
| 内容资产 | skill：四步流程编排 + 科研叙事提示词（发现覆盖、主线/补充、证据关联规则）+ agent 行为约定（冲突先说明、大范围操作先讲计划） |

analysis.md / outline.md / slides.md 的生成本身不写代码，由 agent 执行 skill 产出。工具间衔接全部通过中间产物文件完成，任何工具可被单独调用（如只切图、只拼图、只校验）。

### 5.2 包含

单篇论文四步闭环、自动切图 + 简化调框核对、三个确认点（图源 / outline / slides 渲染前）、outline.md / slides.md 文件化产物与对话式修改、拼图模块、证据关联（内嵌图即关联、疑点标记、覆盖不阻断）、一致性校验。

### 5.3 明确不自研（依赖 dsh / 生态现成能力）

- PDF 文档解析（文本、阅读顺序、表格、图注、整图定位、LaTeX 公式）——官方 MinerU API（OpenDataLab 维护；云端服务，论文 PDF 需上传，配置说明中明示）。**完整流程需高精度模式**：注册 MinerU 账号（mineru.net）→ 控制台获取 API Key → 配置 `MINERU_TOKEN`，或复用原 CLI 的 `~/.mineru/config.yaml`。skill 调用随包 Node runner；用户选择试用时才用免费快速模式（≤10MB/20 页、仅 Markdown、无结构化输出，质量降级）。下载失败保留任务与旧产物，重跑恢复下载，不将传输失败等同文档不可解析。
- Panel 切分算法与 OCR——agent 多模态视觉（harness 托管）+ crop 反馈迭代，本地不建几何/OCR 引擎。
- markdown 与图片预览——统一走 dsh 右侧栏文档预览（`ui-sidebar-documentpreview`），我们只做「打开预览」入口。
- LLM 调用、会话管理、文件系统、权限审批——由 dsh harness 托管。
- PPTX 生成与视觉级预览——交给 dsh 生态插件（推荐 dsh-ppt-maker），我们只保证 slides.md 契约清晰。

### 5.4 不包含（沿用 SmartJC 的排除项并叠加本次取舍）
- 项目列表/项目管理 UI（文件夹即项目）。
- 像素级切分工作台（跨页图块、Undo/Redo）、幻灯片自由编辑器、富文本编辑。
- PPTX 生成器与 PPTX 视觉预览（v1；生态插件路径写入使用说明）。
- 账号、云同步、多人协作、多论文工作区、模板市场、联网补充材料、PPTX 导入。
- 非Story类论文（Review、Meta-analysis、指南、病例报告）与非生物医学领域。

## 6. 与 SmartJC 的功能对应

| SmartJC | dsh-journal-club | 变化 |
|---|---|---|
| PWA 项目列表 + IndexedDB | 文件夹即项目，无管理 UI | 存储换文件系统，管理归用户 |

| pi-agent-core 问答 agent | dsh agent 会话 | 平台原生 |
