# 产品设计

本文定义 dsh-journal-club 的产品行为。技术契约、开发发布与验证边界见 [架构设计](../architecture/架构设计.md)；安装与快速使用见 [README](../../README.md)。

## 1. 定位与边界

dsh-journal-club 是 DeepSeek Harness 内的生物医学文献汇报插件。用户在自己的论文工作目录发起任务，由 agent 分析论文、裁切图源、组织叙事和讲稿，在右侧工作台核对与调整，最终通过生态插件导出 PPTX。

- 完整汇报面向生物医学原创研究；综述、Meta-analysis、指南、病例报告和非生物医学论文不进入完整科学内容生成流程，但仍可单独裁图、拼图或校验。
- 成功标准是证据完整可读、来源可查、讲稿与页面对应。人工检查、调框和整图兜底是正常使用流程，不要求模型一次完成完美切分。
- **文件即真相**：分析、图源、拼图、文稿与确认记录各有普通文件承载。工作台读取文件，不维护另一份项目数据库；浏览偏好和未保存草稿不充当产物事实。
- **工具独立，流程由 skill 编排**：五个原子工具可以单独组合使用，不强迫用户进入完整汇报流程。
- **复用宿主能力**：会话、模型、文件权限、Markdown 和图片预览由 DSH 提供；PPTX 生成与视觉编辑交给 dsh-ppt-maker。监督依靠聊天 diff、工作台高亮与图源快照，不新增编辑审批流。

不建设账号、云同步、项目管理器、论文库、跨页图像拼接、独立幻灯片编辑器或 PPTX 引擎。拼图只处理科研图片，不增加文字、旋转、拉伸、二次裁切和复杂图层。

## 2. 任务入口与完整流程

| 场景 | 行为 |
|---|---|
| 完整汇报 | 在会话工作目录建立论文子目录，复制主论文及可选补充 PDF，创建 `jc.md`，仅在不存在时初始化空 `groups.json`；无需使用插件源码目录 |
| 局部任务 | 就地调用所需工具，不创建完整项目状态或流程卡片；输出位置可由用户指定 |
| 恢复任务 | 读取 `jc.md` 和实际产物，比对确认 revision/digest，从真实断点继续；不凭文件存在或 stage 值跳过确认 |

只有 PDF、意图不明时先确认任务范围。完整流程开始时询问一次时长和重点要求，记入 `jc.md`，不阻塞论文分析，也不据此自行删减主图。

论文身份尚未核实时，先在会话工作目录按 PDF 文件名建临时项目目录、复制主文为 `main.pdf`，调用 `render_pages`（第 1 页、150 DPI）并读图识别标题与论文类型，总页数直接取返回的 `num_pages`。将同一目录改为正式论文名，保留 PDF 和首页图，不覆盖已有项目；再复制补充材料并创建状态文件，不另设起名确认。恢复已知项目不重复识别。默认不为身份、元数据或页数探测/安装 PyMuPDF 等 Python PDF 依赖，全文解析使用随包 MinerU API runner。

**论文分析 → 图源核对并确认 → 叙事大纲并确认 → 幻灯片文稿与拼图并确认 → PPTX 导出。**

| 步骤 | 产物与完成要求 |
|---|---|
| 论文分析 | 解析全文、方法、图注与表格；生成图源候选及 `analysis.md`。底稿包含问题、设计、发现与证据关联，以原文引用和页码溯源，按完整分析单元及时保存 |
| 图源核对 | 检查主论文与补充材料的全部图源，允许人工和对话修改；整体确认前按当前框重裁所有未排除 Panel，再记录最新 revision |
| 叙事大纲 | `outline.md` 组织研究问题、证据单元、计划覆盖与讲述节奏；用户确认后分页 |
| 文稿与拼图 | `slides.md` 给出每页标题、内容、图片、来源与完整讲稿，`groups.json` 保存拼图布局；程序校验与语义自查后，等用户确认内容及拼图效果再渲染 |
| PPTX | agent 读取已确认文稿与图片，使用生态插件创建、检查、导出；交付前核对备注、图片和实际视觉效果 |

三个确认点是 skill 的推进约定，不锁定编辑。每到一处都展示当前产物与对应卡片，结束本轮回复并等待用户；新完整流程首次停图源，图源确认后生成大纲，大纲确认后生成文稿，三项确认有效后进入 PPTD/PPTX。不能先生成后续草稿再补确认；首次“做中文 PPT，15 分钟”、宿主免工具审批或解析失败后的“继续”不自动确认内容。恢复时从最早缺失/失效点继续，已有文稿或 PPTX 不能替代记录。修改图源或文稿后，对应确认失效并提示复核；PPTX 不自动更新。用户明确要求跳过指定确认点或直接渲染已有/当前文稿时按其范围执行，如实保留缺失记录，不伪造确认。

## 3. 学术汇报规则

- **正文主图及所有标号 Panel 默认在正式汇报正文清晰展示**，可整图、拆页或拼图累计覆盖。备份页、部分 Panel 或不可读缩略图不能抵充；仅保留用户明确取舍的例外，缺图如实披露。主图与补图按原论文编号及图注区分，不按 PDF 文件角色区分。
- 时长通过讲稿详略控制：重点实验详讲，并行验证简讲，压缩铺垫和重复说明，保留关键对照与阴性结果。估时包含读图停顿，给出主线区间，备份与问答另计；仍超时则说明差距，不自行删图或虚报时间。
- 结构采用「论文身份 → 背景与知识缺口 → 问题及总体设计 → 按科学问题组织的结果与就近方法 → 综合解释、局限 → 结论与讨论」，按研究类型调整，不强制页数和模板。结果页优先准确结论标题。
- 首次拼图尽量保留原 Figure 的左右、上下、行列分组、相对大小和阅读顺序，按实验或比较单元拆页；对照、共享图例、坐标与统计标注随比较保留。用户指令及已有手动布局优先，可读性或叙事需要改变时简要说明。
- 结论必须受证据约束，不编造、不升级因果；模型模拟、条件子群结果和批评性判断保留适用范围。认定原文矛盾前回查原页，排除识读错误，证据不充分处标 `⚠️`。
- 大纲记录计划覆盖；分页确认时核对实际正文页与主图/Panel 映射并说明例外，不为补最终页码修改已确认大纲。程序负责引用、版本和格式；发现覆盖与科学表达由 agent 自查和人工检查。

## 4. 工作台与导航

右侧 Journal Club 页签顶部保留项目名和「切换项目」，下方是独立的「概览 / 图源核对 / 自由拼图」。聊天卡片只承载摘要、确认及打开入口，长时间编辑留在工作台；文稿和图片预览使用宿主能力。

- 导航优先级：**显式入口 → 当前会话记忆 → 文件实况推荐**。记住项目、页面和选中的 Figure/Panel/拼图；文件更新刷新内容，不擅自跳页。
- 无有效记忆且有多个候选，或用户主动切换时，展示目录列表与已有产物；仅扫描工作目录及一级子目录中的 `jc.md`、`figures.json`、`groups.json`。不提供重命名、删除等项目管理功能。
- 概览以一张「当前状态与下一步」卡为视觉中心，优先显示读取失败、确认异常和已变更内容；下方常显紧凑阶段摘要、最多三项主要产物，其余原因与文件折叠。文件存在不代表完成或确认，PPTX 存在不证明同步，不显示虚构进度百分比。
- 局部切图直接进入核对，局部拼图进入拼图；不要求补齐完整流程。只有图源也可新建拼图；只有图组时仅恢复清单成员对应的已有图片，不扫描散图或自动创建 `figures.json`。
- 切页面和放大编辑保留组件与草稿。写入期间阻止切项目或关闭页签；未保存时提示。内存草稿不抵抗应用退出或插件卸载，需先保存。
- 风格贴近 DSH：共享宿主字体与中性色，交互、选中和焦点用蓝色，主按钮深蓝白字；浅灰分隔，冷灰编辑区衬托白色页面和图片，不改科研图像颜色。窄侧栏响应布局，放大仍用同一编辑器。

插件当前统一注册五个工具，没有逐工具启用的设置页；按已有文件显示可用页面，不从文件存在推断执行授权。

## 5. 图源核对

Figure 按清单顺序连续排列，可折叠并筛选「全部 / 未查看 / 有疑点」。主论文和补充材料在同一列表标注来源与物理页码，已排除图默认折叠。Panel 导航与工具栏随 Figure 滚动，**不吸顶**；整体确认留在聊天卡片和概览，不占核对页固定底栏，局部切图不显示流程确认。

### 页面与操作

- 宽编辑器左侧原始 PDF 页与框，右侧选中 Panel 的标签、裁切预览、疑点及关联图注。两栏分隔条可拖动或用键盘调整，默认约 60:40、支持恢复默认；窄区单栏，保留放大入口。
- 原页外为冷灰底；普通框细蓝边、透明内部，选中框蓝实线、极淡蓝底和白底蓝边控制点；疑点用橙色虚线和文字提示。画布支持适应页面、150% 和 200% 查看，缩放不改变保存坐标。
- 点框或标签选择；拖动框体移动，四角缩放；支持添加、删除 Panel、编辑标签、排除 Figure 和标记已查看。标签 Enter/失焦提交、Escape 取消；删 Panel 与排除图保留确认提示。人工框以原 PDF 页为边界，必要时外扩 Figure region，不移动其他 Panel。
- 框与标签修改即时保存，无独立保存按钮；改框或补图后重裁对应 Panel。预览来自已有页图，正式 PNG 从原 PDF 重渲染。重裁失败保留框并提示「裁切未刷新」，不把旧资产当新结果。
- 选中 Panel 高亮对应图注片段，支持多对多关联与完整图注展开；公共说明只关联适用 Panel。标签修改保留关联并标待复核。
- 「漏了一张图？」可选文件、页码并框出整图，agent 补做 Panel 与图注；失败保留人工框并局部重试。「让 AI 重新识别 / 恢复自动结果」发送限定 Figure 的对话请求；恢复使用现有快照，不建立另一套候选状态。

### 科学完整性与冲突

原文每个字母 Panel 保持独立身份；同一标签内部多坐标轴保持完整，合并展示交给拼图。保留标签、坐标轴、图例、比例尺与统计信息；逐边区分自身截断和邻图串入，不能为边缘干净而切掉证据，也不能反复整体外扩。不抹白、擦除或重绘科研像素。

agent 用 `render_pages` 与宿主读图检查原页，必要时升至 300 DPI；视觉判断框，经 `update_figures` 保存，再用 `crop` 从 PDF 刷新正式资产。不用空白带、亮度阈值或轮廓扫描算法替代视觉切分，也不用 Python/Pillow 脚本另裁页图或覆盖 Panel PNG。当前没有给 agent 的坐标网格/批量核对图接口，常规检查直接读取实际资产或用工作台放大，不自动堆叠标尺、网格和联系图脚本；看不清时保留疑点并使用人工调整或整图兜底。

矩形无法独立保全必要标注时，保留原 Panel 身份与疑点，另加无标签整图参考，说明兜底原因，不计作独立切分成功。原 PDF 已有的异常记为源文件限制。未解决问题同时记录到 Panel flags 和核对说明，不能仅在聊天告知却显示「疑点 0」。

图注断句或后部 Panel 缺关联时，agent 核对相邻页的普通文本、页脚和原 PDF，不能只读解析结果的 image_caption；补全后更新句子与关联，保留图注起始页，页码范围记入底稿。图注跨页补全不等于跨页图片拼接。

工作台与 agent 共用版本保护。写入依次排队，后台刷新不覆盖未提交输入；冲突就地提示并保留输入，用户检查后显式重试。暂时读取失败先重试，仍失败保留上次内容并报错。对话修改与手动调整冲突时先说明，大范围重识别先讲计划；不另设候选审批门。

未查看或剩余疑点提示但不阻止整体确认。优先解决缺图、关键内容截断与错误引用；细微边缘问题如实保留，不因模型能力限制反复打磨。确认前重裁全部未排除 Panel，之后读取 revision 记录确认。

## 6. 自由拼图

### 浏览与编辑

- 左侧缩略图列表上滚轮直接前后切换拼图，也支持点击和键盘，首尾不循环；画布和素材区滚动不切组。当前项高亮并保持可见。
- 有 `slides.md` 时按正文图片首次引用顺序排列，重复引用仅列一次；不再引用、已从清单移除或 PNG 缺失的旧图不显示，旧草稿也不恢复它们。无文稿时按清单顺序；本次新建但尚未引用的图暂留会话末尾。列表过滤不删除磁盘文件，保存不改变顺序。
- 中间为画布，右侧「素材 / 属性」默认素材：按 Figure 分组的完整等比缩略图，可搜索；点图看大图，独立「＋」加入，已加入项可定位。素材延迟读取，失败明确提示；同一 Panel 在一个图组中只保留一个成员身份。
- 拖动移动、四角等比缩放、方向键微调，Shift 加大步长；空白或 Escape 取消选择，Delete/Backspace 移出图片，不删除原图。输入框保留文字快捷键。图片可重叠，按成员顺序绘制，选中不改变层级。
- **不限图片数量与画布比例**。图片可移到旧范围外或负坐标；默认适应当前全部图片，手势中固定坐标，结束后自动取景，手动放大仍可滚动。「查看全部图片」回到适应模式。
- 编辑区用冷灰底，白色导出区以灰色细实线和微阴影标边，选图及控制点用蓝色。保存按图片实际外缘导出，去外围空白、保留内部间隔和原图全部内容；拼图是 PPT 中的图片素材，不是整页幻灯片。
- 新增图片错位放置，不重排已有内容；「建议排版」是可撤销的几何建议，不调用模型。原文排列参考属于 agent 提示词约定，不声称该按钮识别了论文语义。移动/缩放一次手势记一次撤销，保留最近 60 步内存历史。

### 保存、图源更新与对话

**修改已有拼图始终保留原 ID 和 PNG 路径；只有明确新建/另存才产生新身份。** 不因改成员或布局自动改名，不按成员相同自动合并；保存原位更新清单，文稿引用保持有效。

agent 正式拼图使用 `compose_panels`，工作台保存使用共用导出核心的 `saveComposition`。不以图像脚本直接缩放、粘贴并覆盖组合 PNG，不绕过成员指纹、布局与清单登记；核对用联系图不登记为汇报图组。这些约定只限制图源/拼图资产，不限制派生 PPT/PPTX 的生成或兼容性排错脚本。

发现裁切问题时，回图源核对调框并重裁，再回拼图点「刷新图源」：保留当前成员、坐标、包围框和撤销历史，按新图比例等比适配，随后自动保存并重新渲染当前组合图。其他受影响图组只标待保存，不批量重排或级联重建。

保存和刷新失败、素材缺失或外部布局冲突时保留草稿并报错。普通图源刷新不能解除布局冲突；「重新加载布局（放弃当前草稿）」显式读取外部版本。当前图已移除时不重新创建。资源不足报告实际错误，不用固定图片数量限制代替处理。

「加入对话」复用宿主输入框插入图组 ID、PNG 与清单文件引用，明确原 ID 和输出路径，用户补充意见后自行发送。需要时先保存；保存失败不引用旧图。插入不自动发送、不覆盖已有文字，期间输入版本变化则提示重试。AI 改动布局后工作台自动重读；有未保存手动草稿时保留它并提示重载，不静默覆盖，保存或拖动期间延后刷新。

## 7. 文稿、渲染与交付

`analysis.md` 保存证据分析，`outline.md` 保存叙事计划，`slides.md` 是唯一幻灯片内容源。文稿用相对图片路径关联图源或拼图，包含来源和可见讲稿；具体格式见 [架构中的文稿契约](../architecture/架构设计.md#44-文稿契约)。维护通过对话或普通编辑器完成，预览走宿主 Markdown。

渲染前修复校验错误；覆盖、图文对应、来源过期等提醒需解释。agent 逐页核对正式正文主图覆盖、图的可读性及讲稿，不把格式通过等同于科学质量通过。

agent 先激活已安装的 ppt-maker skill、发现实际工具，再创建 PPTD、检查和导出。每页讲稿完整转入讲者备注，仅去掉 Markdown 格式，不摘要改写；讲述提示保留在备注，不进入投影正文。图片元素框保持原图比例。

PPTD/PPTX 是派生物，内容修改回到 `slides.md` 后重新生成；外部工作台的纯视觉微调不回写文稿。交付前检查备注全文、图片、来源和页面视觉；外部预览异常时用 PowerPoint 等独立查看器复核，不仅凭 XML 或文件存在宣称视觉通过。
